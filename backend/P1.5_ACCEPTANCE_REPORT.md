## 5. AC-16：性能、资源与 Agent A 后台可用性

### 5.1 Probe P50/P95

| 场景 | 样本/并发 | 错误 | client P50/P95 (ms) | server P50/P95 (ms) |
|---|---:|---:|---:|---:|
| 空闲 | 120 / 1 | 0 | 13.357 / 20.529 | 4.567 / 5.448 |
| 空闲 | 160 / 4 | 0 | 33.320 / 84.523 | 13.604 / 57.391 |
| 合成 Builder 负载 | 160 / 4 | 0 | 33.304 / 43.652 | 13.782 / 19.188 |
| 合成 Builder 负载 | 120 / 1 | 0 | 16.155 / 20.145 | 4.568 / 5.569 |
| Agent A 运行时（FunctionModel） | 160 / 4 | 0 | 33.115 / 49.421 | 13.149 / 23.143 |

合成 Builder 负载：45 秒内完成 58,564 次 PostgreSQL 只读计数 + CPU 自旋；
负载容器 CPU 约 50.34%，内存约 45.57 MiB；retrieval CPU 约 19.45%，
内存约 68.76 MiB；postgres CPU 约 13.07%，内存约 61.76 MiB；api 内存约 68.94 MiB。
所有阶段 0 错误，P95 远低于 3000 ms 门槛。

Agent A 运行时压测：作业 `c0af4485-7cad-45f9-ada7-a8fb99531579`，
状态 `partial`（自主覆盖不足，非执行失败），`model_mode=TEST_FUNCTION_MODEL`，
`model_requests=6`、`tool_calls=29`、`duration_ms=3807`，
采样峰值 CPU 84.1%、峰值 RSS 105,451,520 bytes（约 100.6 MiB）。
Probe 开始时作业已处于 running；4 并发 160 次请求全部 200，墙钟 1.38 秒，
吞吐 115.96 req/s。该作业使用 FunctionModel，不计真实模型费用。

### 5.2 解释限制

- 空闲 4 并发 P95（84.5 ms）高于负载 P95（43.7 ms），是短窗口、小样本与调度噪声，
  不能据此得出“负载更快”或“负载无影响”的结论；本报告只陈述实测值。
- 负载是合成 CPU + 只读 SQL，不是真实 Agent A 的模型网络延迟、长上下文或工具调用；
  FunctionModel 也不代表真实模型能力。
- 公开 12 文件样例不是企业规模；没有做独立 4C8G 虚拟机、长时间稳定性或容量规划测试。

## 8. 剩余风险与未完成项

1. **未在独立 4C8G 虚拟机测试**：当前数据只适用于 Docker cgroup 配额开发环境。
2. **未做真实模型能力验收**：P1.5 只复用历史真实记录；FunctionModel 不是真实模型。
3. **未做企业规模/长稳测试**：12 文件人工样例不能代表真实源码规模、并发峰值或长时运行。
4. **语义能力有限**：Probe 只做确定性词法匹配，不提供语义索引、合规判断或等效性结论；
   这些缺口在响应中显式返回。
5. **标准 pytest 不跑真实 PG**：真实 PG 一致性结论来自独立 schema 的 18 项测试；
   SQLite 结果不作为 PostgreSQL 锁/隔离证明。
6. **本地验收数据会影响重复运行**：会新增测试品类/任务/报告；不要在生产库执行验收脚本。
7. **Agent 负载作业为 partial**：是自主模式覆盖上限造成的业务状态，不是进程失败；
   该结论只用于可用性/延迟测试。
8. **未进入 Agent B**：能力合并、自动审核/发布等均未实现，符合本轮范围。

## 9. 结论

在开发 Compose 环境、人工公开样例和合成/FunctionModel 负载边界内，P1.5 的只读 Probe
满足 §9 契约与 AC-14/AC-16 的开发验收目标：读取当前生效发布、逐字段可追溯证据、
严格只读与作用域校验、无合规结论、发布切换/回滚一致、Agent A 后台运行时可用且
P95 远低于门槛。真实模型能力、独立 4C8G 虚拟机性能和企业规模容量仍需后续专项验收；
本轮不将上述结果外推为生产能力承诺，也不进入 Agent B。
