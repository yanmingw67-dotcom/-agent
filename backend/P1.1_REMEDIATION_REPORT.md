## 1. 队列一致性整改

KnowledgeJob 继续充当 durable outbox，不引入第二队列框架：
1. 在数据库事务中加锁认领 queued 任务，提交 dispatch_token 与 dispatched_at 租约。
2. 事务成功退出后才调用 Redis/RQ enqueue，Worker 立即领取也可见相同令牌。
3. enqueue 后另一个事务写入 dispatch_enqueued_at；新增 Alembic 0002，保留迁移 0001 原样。
4. 投递失败释放租约；确认结果未知也用同一个消息 ID 重发。未投递/未确认就退出，
   由已提交租约超时扫描恢复；不是延长超时来掩盖原竞态。
5. Worker 依赖数据库行锁 + queued 状态 + token 去重；显式 retry 开始新 attempt 才换 token。
6. RQ 同一 ID 重复入队确实可能出现，但真实测试证明只产生一份有效提取结果。

不承诺跨数据库/Redis exactly-once 消息投递；采用至少一次投递和业务幂等领取。
真实数据库 commit 响应丢失和所有断电/kill 点未穷尽验证，见专项计划。

## 2. 二进制/编码边界

整个流检查 NUL，后 64 KiB 出现 NUL 会移除已写临时文件并标记
binary_or_unknown_encoding，完整哈希/展开限额仍有效。
带 BOM UTF-16/32 在全流解码有效时保留原始字节，标记 encoded_text_pending；
这不是已实现的文本索引。无 NUL 文件为 text_candidate，不保证一定是文本。
不支持的无 BOM 编码仍归入待适配范围；原始归档及排除报告保留，不静默丢失来源。
