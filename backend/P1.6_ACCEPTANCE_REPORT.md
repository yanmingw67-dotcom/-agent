## 3. 交付内容

### 3.1 迁移与数据模型

- 新增 Alembic 迁移 `backend/app/db/migrations/versions/0008_dual_source.py`，revision `0008`，下游 `0007`；未改写 0001～0007。
- `source_snapshots` 增加 `derived_from_snapshot_id`、`derivation_type`，记录暂存派生关系。
- `documents`、`capability_claims` 增加 `origin_json`；`capability_claims` 增加 `source_channel`。
- `claim_revisions` 增加 `availability_basis`、`product_scope_confirmed`、`proof_kind`、`conflict_ids`，均可空或带默认值，旧审核记录保持可读。
- 新增 `document_discovery_runs`：模式、状态、预算、覆盖缺口、检查点、`model_mode`。
- 新增 `conflict_findings`：类型、双方候选、未解决/已裁决状态、人工裁决记录，唯一约束 `uq_conflict_finding_pair`。

### 3.2 文档结构恢复

实现 `backend/app/knowledge/document_structure.py`，复用现有 DOCX/XLSX/PDF/MD/TXT 解析器，不重写解析器：

- DOCX：标题层级、段落、表格、表头、行号、列标题、合并单元格上下文、章节角色。
- XLSX：Sheet、表头行、A1 坐标/区域、功能/参数列角色、合并分类继承、未来规划/证明材料 Sheet 排除。
- PDF：页码、表格单元格、page_text 与表格双重提取去重、`ocr_required` 显式缺口。
- MD/TXT：标题、项目符号、使用条件与未来规划章节。
- 所有单元保留 `document_id + segment_id + locator`，不生成模型虚构页码或 Sheet。

### 3.3 文档独立发现

实现 `backend/app/knowledge/document_discovery.py`：

- 结构优先分类，关键词只作受限语义补充；列角色和章节角色优先决定用途。
- 排除证明材料、友商对比、商务服务、未来规划、法律声明、低价值标题。
- 每个候选登记真实 `Evidence`（`kind=document`），写入文档专属 Module `__document__:<id>` 与 `origin_json`。
- 记录文档数、单元数、候选数、跳过数、重复数、预算上限、覆盖缺口、耗时；预算耗尽显式 `partial`/`truncated`。
- `model_state()` 明确区分 `NOT_USED`、`UNAVAILABLE`、`NOT_INVOKED`；未配置或未授权时不会伪装成真实模型结果。

### 3.4 双源冲突与归并

实现 `backend/app/knowledge/conflicts.py` 与 `backend/app/api/conflicts.py`：

- `support_exclusion_conflict`：同名功能一条支持、一条排除。
- `possible_duplicate`：同快照跨来源同名，仅提示人工复核，不自动合并。
- 未解决冲突阻断接受与发布；管理员裁决必须 `human_confirmed=true`，记录解释、裁决人、时间与审计事件。
- 不把支持范围与限制条件做并集；候选始终保留各自出处。

### 3.5 审核门槛来源等价

修改 `backend/app/knowledge/quality.py`：

- 每项断言必须有非测试源码或同快照有效文档证据；文档证据必须能解析回产品能力单元，引文必须与单元原文匹配。
- 文档单源需要四项显式确认：`proof_basis=document`、`document_scope_confirmed=true`、`availability_basis=document_declared|mixed`、`product_scope_confirmed=true`；混合源使用 `mixed`。
- 文档单源可豁免源码运行时接线；源码路径的接线、跨文件实现链、调用方证据等原有约束保留。
- 高风险措辞（隔离、原子、幂等、持久等）若由文档明确声明，按文档明示范围支持产品级能力，不强制伪造源码实现链；双源同样以文档明示范围为准。
- 新增扩大化措辞阻断：断言中出现“所有/全部/任意/零丢失/强事务/100%/全局一致”等，而文档引文没有对应表述时，返回 `DOCUMENT_SCOPE_EXPANSION`，不进入审核通过。
- 发布前 `publisher.validate_revision()` 重跑同一门槛，未解决冲突返回 `PUBLICATION_CONFLICT_UNRESOLVED`。

### 3.6 文档暂存更新与发布回滚

实现 `backend/app/knowledge/document_staging.py` 与 `backend/app/api/indexing.py`：

- `POST /api/v1/categories/{cid}/document-staging-snapshots`：从当前受控源码快照物理派生新暂存快照，新 `snapshot_id`、`derivation_type=document_update`；校验 manifest、归档哈希、物理文件哈希，复制源码归档并重新解压，复制文档文件与分段，不共享旧文件。
- `POST /api/v1/snapshots/{sid}/documents/{did}/replace`：在派生暂存快照内替换文档，重新解析/索引，写 `origin_json.replaced` 与旧文件哈希。
- `DELETE /api/v1/snapshots/{sid}/documents/{did}`：移除暂存文档及分段；被证据引用的文档返回 `DOCUMENT_IN_USE`。
- 已发布快照禁止直接修改，返回 `DOCUMENT_STAGING_REQUIRED`；旧发布、旧清单、旧物理文件在切换前保持不变。
- 新快照发布后旧发布仍可按 `publication_id` 回滚，清单哈希与证据精确复原。

### 3.7 Probe 兼容

`backend/app/retrieval/probe.py` 继续只读 P1.5 冻结发布：

- 文档证据可返回 `source_ref.document_id/segment_id`、`locator`、`quote`、`quote_hash`、`source_hash`。
- 原文件或分段哈希改变、文件删除时 fail closed，返回 `DOCUMENT_HASH_MISMATCH`、`SEGMENT_HASH_MISMATCH` 或 `EVIDENCE_SOURCE_UNAVAILABLE`，不继续把旧内容当可信证据。
- 未发布候选、内部覆盖明细、后台调查任务不进入普通 Probe 响应；保留 P1.5 安全 `coverage_summary`。

## 5. 真实模型边界

- 本轮未获得企业文档外发授权，未向任何外部模型发送企业或合成文档。
- 文档发现验收使用确定性结构发现（`document_discovery_mode=structural` 默认行为），不是真实模型能力验收。
- `model_state()` 对未配置/未授权/未调用分别返回 `UNAVAILABLE`、`UNAVAILABLE`、`NOT_INVOKED`；报告不把结构规则结果称为真实模型结果。
- 未使用 FunctionModel 作为“真实模型通过”的证据；如后续接入模型，仍需单独授权、预算、证据锚点与人工审核，不能用模型输出替代 evidence_id。

## 6. 安全、资源与数据

- 测试资料全部为人工合成公开 fixture（`backend/tests/p16_assets.py`），不含企业真实 Excel、源码或文档；未把上传目录或真实企业数据提交仓库。
- 文档解析沿用既有受限解析器：Office 归档预检、条目数量/大小限制、XML 实体禁用、XLSX `read_only=True`、`keep_links=False`，公式不执行；不执行宏、源码脚本或外链。
- 文档证据回读校验原文件 SHA-256 与分段文本哈希；跨快照/跨品类拒绝；不可变修订、发布前重校验、原子发布/回滚、已发布冻结保留。
- 证据链：`evidence_id → document_id → segment_id → locator → quote_hash` 在 Probe 文档单源测试中逐项断言。

## 8. 原始失败与修复记录

1. **双源审核 422 `REVIEW_GATE_FAILED`**
   - 现象：混合证据断言进入高风险分支，返回 `DEPENDENCY_EVIDENCE_GAP`、`HIGH_RISK_IMPLEMENTATION_GAP`。
   - 原因：高风险分支只允许“无源码、仅文档”，混合源仍要求跨文件实现链。
   - 修复：文档存在时按“文档明示范围 + 严格范围确认”支持高风险产品级声明；源码单源路径保持不变。回归 P1.4 审核测试全部通过。

2. **暂存回滚测试比较重新生成的 DOCX 字节**
   - 现象：同一文档重新生成后 ZIP 时间戳不同，物理文件字节比较失败。
   - 修复：在替换前捕获旧文件原始字节，比较原文件是否保持不变，而不是比较重新生成的 fixture。

3. **暂存更新候选名称不一致**
   - 现象：测试按“策略模板导入”查找，实际候选名为完整句子。
   - 修复：按真实候选名“当前版本支持策略模板导入，模板由管理员维护。”审核与 Probe 断言。

4. **分段哈希测试改错对象**
   - 现象：修改文档第一个分段，但该分段未被断言引用，Probe 仍返回候选。
   - 修复：从审核修订的 evidence_id 追溯实际 segment_id 再篡改；并补充文件删除场景。

5. **文档范围扩大检查类型错误**
   - 现象：`documents` 已是证据字典列表，仍按 evidence_id 索引，触发 `TypeError: unhashable type: 'dict'`。
   - 修复：直接读取证据字典的 `quote` 字段，并补充扩大化断言阻断测试。

6. **规范检查**
   - 修复未使用导入、未使用局部变量、导入排序与格式化问题；最终 `ruff check` 与 `ruff format --check` 均通过。
