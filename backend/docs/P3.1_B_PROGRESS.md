## 一、目标与结论

P3.1-B 要回答三个问题：

1. 能否从干净状态独立启动验收环境，任务真实经过后台队列，重启可恢复，失败可查且重试安全。
2. 能否在真实源码、正式技术文档和模型授权齐备后，完成真实知识构建、人工审核与发布。
3. 能否用真实招标文件完成符合性评估，并产出 All/Some/None 结论与导出物。

本轮结论：

- **Gate 1 PASS**：独立 Compose 项目可从干净状态启动，21 项检查全部通过；任务真实进入 Redis 队列；重启后数据一致；失败码与重试行为正确；权限边界有效。
- **Gate 2 BLOCKED**：没有管理员确认的真实 WAF 源码来源，没有确认的正式技术文档，服务器侧模型未配置，没有企业数据模型外发授权记录，没有真实知识发布物。
- **Gate 3 BLOCKED**：真实招标结构提取 10/10 通过，但没有真实发布知识，评估入口按设计返回 409 `KNOWLEDGE_NOT_PUBLISHED`；没有产生产品符合性结论或导出物。

因此不能宣称 P3.1-B 完成，也不能用 Gate 1 的合成样例或 Gate 3 的结构提取结果替代真实产品验收。

### 3. Gate 2 来源、授权与派生链核验

原脚本把“哈希不在合成集合”当作真实资料的充分条件，无法防止拼凑或未审批外发。本轮拆为只读采集脚本与纯核验模块：

- 真实源码必须由管理员确认来源、适用范围与确认依据，且是根快照、已索引、企业分类。
- 真实文档必须由管理员确认，且属于声明快照、已解析、有正文分段、企业分类。
- 模型授权必须是数据库记录，匹配当前模型名、完整端点路径与数据分类；环境变量不构成审批。
- 文档发现必须 `succeeded` 且非 structural。
- 发布物能力必须来自发布快照，修订为 `accept`、最新修订且审核状态为 `human_accepted`。
- 源码、文档、发现与发布物必须同品类、同根派生链；跨来源拼接 FAIL，缺输入 BLOCKED。

本轮结果：真实来源、授权、发现与发布物仍未就绪，Gate 2 保持 BLOCKED。证据：`docs/acceptance/p31b_gate2.log`、`p31b_gate2_evidence.json`。

### 3.1 R01：模型外发授权闭环

- 新增 `model_authorizations` 表与迁移 `0013`，只新增表，不回填历史授权。
- `configured_model` 在构造真实模型前查询有效授权记录；无记录返回 `MODEL_AUTHORIZATION_RECORD_REQUIRED`。
- 授权登记/撤销使用独立 `MODEL_OPS_TOKEN` 与 `X-Model-Ops-Token`；未配置令牌返回 503。
- 本轮验收环境未注入 `MODEL_OPS_TOKEN`，未登记任何授权记录；模型授权检查保持 BLOCKED。
- 实环境探针：无运维令牌登记返回 503 `MODEL_OPS_NOT_CONFIGURED`，授权列表为空。证据：`docs/acceptance/p31b_r01_live_negative.log`。
- 授权记录不会自动打开 `BUILDER_ALLOW_ENTERPRISE`；开关关闭时真实调用仍返回 `MODEL_DATA_NOT_AUTHORIZED`。

### 3.2 R02：资料来源与派生链闭环

- 新增 `material_provenance` 表与管理员确认/撤销入口。
- 源码必须是根快照；技术文档必须已解析且有分段；合成分类或已知合成哈希硬拒绝。
- 新增派生链核验接口，检测父快照缺失、跨品类派生、循环、深度超限与元数据不完整。
- Gate 2 只有在源码、文档、发现、审核发布物同品类同源时才可能 PASS。

本轮结果：6 PASS、8 BLOCKED；`build_commit=d64d7db`。证据：`docs/acceptance/p31b_gate2.log`、`p31b_gate2_evidence.json`。
