### 7. 大容量源码 ZIP 上传与容量验收（2026-11-23）

目标是在不关闭任何安全校验的前提下，让 747 MB WAF 源码 ZIP 在独立验收环境完成浏览器上传、安全解压和索引。普通售前文档仍保持 100 MiB 请求体边界，不随源码上传一起放大。

| 限额 | 调整前 | 调整后 |
| --- | --- | --- |
| 管理员源码 ZIP 单次上传 | 100 MiB | 1 GiB |
| 单个解压文件 | 20 MiB | 128 MiB |
| 解压总量 | 500 MiB | 4 GiB |
| 普通路径请求体 | 100 MiB | 100 MiB（不变） |
| multipart 表单开销 | 无独立预算 | 仅源码路径增加 8 MiB |
| 受控存储配额 / 最低剩余 | 10 GiB / 1 GiB | 16 GiB / 2 GiB |
| 解压任务超时 | 300 秒 | 3600 秒（有界） |
| 条目数 / 压缩比 | 20000 / 100 | 20000 / 100（未取消） |

实现要点：

- `RequestGuard` 只对 `POST /api/v1/categories/{id}/source` 使用 `max_upload_bytes + multipart_overhead_bytes`，其余路径继续使用 100 MiB；超限在读取请求体前返回 413。
- Nginx 设置 `client_max_body_size 1100m`，关闭 `proxy_request_buffering`，避免请求临时文件与归档双份占盘；超时提高到 3600 秒。
- Starlette 大于 1 MiB 的上传会落临时文件，容器设置 `TMPDIR=/data/tmp` 并挂载独立命名卷；Dockerfile 创建 `/data/tmp` 并由应用用户持有，避免 128 MiB `/tmp` tmpfs 截断 747 MB 上传。
- ZIP64 从“一律拒绝”改为安全支持：校验 EOCD 定位器、记录长度、单卷、偏移边界、中央目录结束位置与条目数；损坏、缺失定位器或多卷仍分别拒绝 `ZIP64_UNSUPPORTED` / `MULTIDISK_UNSUPPORTED`。
- 源码上传在预留数 GiB 容量前先检查同品类是否有 `queued/running` 导入任务，冲突直接 409，避免把业务冲突误报为 `STORAGE_QUOTA_EXCEEDED`；事务回滚保持原有 Conflict 语义。
- `ENOSPC/EDQUOT` 映射为 `STORAGE_LOW_SPACE`，写盘失败映射 507；失败时清理临时文件和容量预留。
- 前端拆分“上传中 / 上传成功 / 解压中 / 解压成功 / 索引中 / 索引成功”，显示 XHR 上传百分比、文件大小与错误码中文说明，不再把 202 当成完整成功。

### 8. 真实 WAF 源码 ZIP 导入专项（2026-11-23）

真实归档 `b0e41631-20d0-494a-bde8-7cc2a5ad415a.zip`（783,596,867 B，SHA-256 `cf3c8c88fb4f48ce5219cd0d0a0ae4841638acec75a5a69d429129565a67fcbf`）首次导入失败，任务 `0324f27e-cd22-4a1a-aeec-323283a3effa` 为 `status=failed`、`stage=failed`、`error_code=UNSAFE_PATH`、`attempt=1`、`model_requests=0`。

根因不是容量，而是路径/排除策略过严：

1. 4 个合法文件名含冒号（如 `frontend/scripts/ci:publish`），旧逻辑一律拒绝；
2. 6 个符号链接在旧逻辑中直接触发 `LINK_OR_SPECIAL_FILE`；
3. `.git/objects/pack` 中 758,845,614 B 的 pack 文件本应排除，却在排除前命中 128 MiB 单文件上限；
4. macOS ZIP 的 6,171 个条目全部未设置 UTF-8 标志，文件名按 CP437 解码后乱码。

修复方式：

- 允许非盘符冒号；继续拒绝盘符、绝对路径、`..`、反斜杠、NUL、控制字符、尾随点和尾随空格；
- 符号链接/特殊文件只记录为 `LINK_OR_SPECIAL_FILE` 排除项，不读取、不落盘、不跟随；
- `.git`、`node_modules`、`__pycache__`、`__MACOSX` 等缓存/生成目录和系统元数据先排除，不参与单文件/总量/压缩比预算；
- 未设置 UTF-8 标志时尝试 CP437 → UTF-8 还原，并重新执行全部路径安全校验。
