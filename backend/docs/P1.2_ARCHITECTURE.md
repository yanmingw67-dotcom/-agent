# P1.2 架构与运行边界

## 第一轮审核整改（优先于下文初版描述）

- 迁移0004：documents.parse_details记录PDF逐页状态和Sheet合并区域，修复旧文档任务
  造成的源码index_status误标；不改已发布指针。解析器版本升级p12-2，暂存快照显式build可重建旧结果。
- snapshot.index_status只表示源码索引；文档状态独立，运行/失败回调/失联/重试均不覆盖源码状态。
  source_index任务整体可因文档partial而partial，但完成的源码仍indexed；不是发布条件已满足。
- PDF空白/无文本页单独记录empty_page或ocr_required，有文本页正常保存；混合文档partial仍可检索。
  整份无文本PDF保留ocr_required兼容状态，无假文字分段。
- XLSX全部合并区域只在文档parse_details.sheet_merged_ranges保存一次；
  每个有值单元格仅携带所属合并范围（openpyxl合并区只有左上角有值），公式不求值。
- rg按固定文件顺序枚举；每文件上限为全局cursor+limit+1，不再固定31。
  达到该动态上限前必已得到一页及前瞻，因此不会隐藏后续页；同编码分组先UTF-8后UTF-16/32，
  各组按路径排序。翻页需保持同一查询/过滤条件且索引不变，重新build后应重启分页。
- next_cursor按实际返回条数推进，引用按路径/行号/边ID稳定排序；超时truncated=true，
  若无结果cursor可不变，表示本次未完成，不能无限机械重试或解释为不支持。
- 新coverage_incomplete独立于分页truncated：大文件/异常编码/排除、未完成源码索引、
  partial/失败/待解析文档即使无命中也声明覆盖缺口；truncated=false仅表示可检索范围当前查询穷尽。
- R07流式大文件正文检索/片段回读尚未实现，2MiB AST/内容边界保持；不可将缺口当产品不满足。
- 正式独立4C8G VM及真实产品规模仍未验证；整改详见P1.2_REMEDIATION_REPORT.md。


## 数据流

管理员导入 ZIP → 原 P1.1 source_import 队列 → extracted。
管理员 POST /snapshots/{id}/build → source_index outbox → 独立 indexer → indexed。
管理员上传文档（显式后台 snapshot_id）→ document_index → 同一受限 indexer → 文档分段。

源码快照 status 保持 P1.1 的 extracted/published 不变量；新增 index_status 表示
not_indexed/queued/indexing/indexed/partial/failed。indexed 不等于已发布知识库。
普通只读请求只按品类绑定 active_snapshot_id；本批无发布接口，首次构建后普通只读请求
仍返回 KNOWLEDGE_NOT_PUBLISHED。管理员可用后台 snapshot_id 调查暂存索引。

## 进程和资源

|服务|CPU 上限|内存上限|职责|
|---|---:|---:|---|
|api|0.5|512 MiB|鉴权、接收导入、任务和管理接口|
|worker|0.5|768 MiB|原始 ZIP 静态校验和解压，写受控暂存卷|
|indexer|1|1536 MiB|单任务逐文件/逐文档索引，源码及文档输入只读|
|retrieval|1|768 MiB|独立快速检索，不消费索引队列|
|postgres|0.75|1536 MiB|持久化/结构化索引/文档全文索引|
|redis|0.25|256 MiB|RQ 和索引 Worker 租约|
|总上限|4|5376 MiB|预留操作系统及容器引擎内存；模型不在本机运行|

indexer 不挂载 archives、control 或可写 ingestion；不可修改原始归档。
Redis 单 indexer 租约 + 单 RQ Worker 串行运行；每轮最多一项索引任务。
各类任务仍沿用 P1.1 的提交后投递 outbox、稳定消息 ID、数据库领取去重。
每文件事务提交独立检查点，失败 retry 保留已完成文件；同快照相同哈希/解析器版本跳过。
暂不做跨快照复制缓存（避免误拼不同源码来源），不同快照独立索引。

retrieval 使用 PostgreSQL 默认只读事务和独立连接池，根文件系统及源码只读挂载，
不注册上传/建品类/构建/存储扫描路由；数据库账号仍沿用本批单应用账号，
默认只读事务不是额外独立数据库权限角色，企业正式部署应按需拆分账号。
api 为兼容和后台调试也提供相同检索路由；未来 Agent B 应调用独立 retrieval 端口。

## 数据与解析

迁移 0003 新增 source_files/code_symbols/code_edges/documents/document_segments/modules/entrypoints，
快照新增 index_status；文档 simple FTS GIN 索引同时在模型中登记。
正文索引首先用 ripgrep 精确搜索，符号/路径用数据库范围过滤；
文档支持 FTS 与子串定位，不启用向量索引，明确 semantic_index_unavailable。

Tree-sitter 实测 Python、Go：函数、类、接口、方法；不支持的语言为 unsupported，仍可文本检索。
文件角色标记 test/source，不将测试函数或入口候选解释成产品能力。
模块由顶层目录识别；入口基于 AST 注册调用、main/事件命名和配置文件启发式，
status=unresolved_candidate，业务含义与运行时可达性未验证。
调用边仅记录语法调用；find_references 返回同名候选并明确 unresolved，
不伪造精确跨模块调用图。

单次只加载一个 <=2 MiB 源文件（超限保留元数据），最多 20000 个 AST 输出项；
清单由 P1.1 ZIP 条目限额约束，不加载全仓库源码正文。
UTF-8、带 BOM UTF-16/32 可解码与准确回读；无法解码标记 invalid_encoding。
UTF-16/32 关键词搜索经解码后送入受控 rg 标准输入，不执行源码。
异常编码、排除文件、过大文件等在 source_files 中有状态和错误码。

文档输入 <=20 MiB，Office 容器先安全检查条目/限额/CRC/DTD；
DOCX 段落/标题/表格，PDF 页与表格 bbox/单元格，XLSX Sheet/单元格/合并区域，
公式只保存字符串，不求值，keep_links=False。MD/TXT 保留行号与章节。
文档按单文档事务写入受限分段，失败不暴露半份分段；扫描 PDF 标记 ocr_required。
PDF 表格提取是启发式；不支持 OCR、宏、嵌入对象和复杂版式精确重建。

## 共享工具

RunContext 为服务端创建的冻结强类型对象，绑定品类/快照/角色/策略；
ToolRequest 不允许模型提交 category_id/snapshot_id/根路径/命令字段。
ReadOnlyTools 提供：
- get_project_map / get_module_context / list_entrypoints
- search_code_batch（literal/受限 Rust regex）/ search_symbols / search_paths
- read_source（file 或 symbol）/ find_references
- search_documents / read_document（分段原文定位及哈希）

工具经 execute(ToolRequest) 统一调用；统一 envelope 附 snapshot_id、truncated、
next_cursor、warnings、duration_ms。不实现 register_evidence 或能力候选工具；
它们属于 P1.3，不提供固定假证据。

get_module_context 提供模块文件/解析状态、最多10个AST符号和5条按模块名词法命中的文档候选；
文档候选不是已核验模块链接，依赖关系明确未解析，更多符号/文档/入口用对应工具追加查询。
项目地图不等于完整覆盖调查。
关键词默认最多30命中；结构化查询最多100项；单次回读<=200行；
片段累计<=24000字符；命中行重新核验文件哈希。分页/预算截断显式标记。
敏感文件或文档分段默认不返回原文；敏感检测仍为启发式，不承诺完整 DLP。

## 性能与完整性

搜索 rg 使用无 shell 固定程序、查询参数、安全文件清单、正则编译容量限制及3秒时间预算。
DB 连接3秒，statement_timeout=3秒，lock_timeout=2秒；池大小4+2，池等待3秒。
检索服务并发连接上限16，keepalive5秒。预算是各执行层边界，不是整个 HTTP 请求统一硬 SLA。
大范围无命中 rg 检索可能返回 partial/truncated，不能把截断当完整无结果。

metrics 为各进程内计数/总耗时/最大值/最近512样本 P50/P95，重启清零，
数据库指标不包含 SQL/参数；请求日志不记录检索词或源码。
任务记录 CPU 时间、ru_maxrss、50ms CPU/RSS 峰值采样、文件数与耗时；
Docker stats 采样记录容器合计内存（含父进程/子进程/cache），不等同于单任务 RSS。
这不是完整 Prometheus 或跨进程指标聚合平台。

## 存储约束

capacity 使用受控 control 卷 flock + 原子 JSON 账本，兼容本地 POSIX 卷；
上传前按最坏上传+展开+清单预留，Worker 解压前重新确认；已用量、其他在途预留
与文件系统 free space 共同检查。文档上传同样预留；不由文件名决定磁盘位置。
默认受控文件 quota10GiB，最小可用1GiB；不包括 PostgreSQL/Redis/模型/容器镜像占用。
数据库与宿主机卷仍需部署级配额和监控。此限制是应用合作式受控写入限制，
不是防止管理员或容器外直接写卷的文件系统硬配额。

失败释放预留；进程异常退出保留残余预留，保守拒绝超额写入。
GET /admin/storage 为只读扫描，包括引用状态、在途保护、孤儿候选和残余预留。
不自动删除归档/快照，不释放未经核对的崩溃预留；需管理员排查并在暂停写入时处理。
扫描文件清单而非全文，数据规模很大时可能较慢；独立检索服务不执行该扫描。
