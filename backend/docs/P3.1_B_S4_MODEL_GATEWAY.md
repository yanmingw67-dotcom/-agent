**结论：本地授权门禁已验证；真实网关与 Agent A 企业调查均为 BLOCKED。** 未收到网关地址、模型、密钥或真实审批依据。不要把来源确认、健康检查或合成试验当作企业批准。未上传资料、启动真实调查或发布知识。

## 客户端能力与边界

|项目|当前实现与验收边界|
|---|---|
|传输|Agent A 使用锁定版本的 OpenAIChatModel 和 AsyncOpenAI；Bearer Key、自定义模型名。Base URL 填企业批准的 HTTPS 基地址，包含版本及租户路径，不填最后的 /chat/completions；客户端在其下追加 chat/completions。绑定协议、主机、端口及完整基路径，忽略末尾斜杠；禁止凭据、查询参数、片段，不跟随重定向。|
|工具与 JSON|Agent A 使用函数工具和类型化输出，依赖模型返回可解析的 tool_calls 与 JSON 参数。部分流程明确要求 parallel_tool_calls=false；reasoning_effort 默认不发送。严格 response_format=json_schema 是独立能力，工具参数正确不等于支持原生 JSON Schema。不能据“兼容”字样推断这些能力。|
|上下文与超时|本地默认上下文预算 80,000 字符，单请求另有消息封装余量；不能换算成网关上下文窗口。模块默认 8 次请求、30 次工具、30,000 token，单输出上限 4,000。HTTP 超时 60 秒，SDK 自动重试 0；Agent 可对无效输出纠正 1 次，不等同于网络重试。网关实际模型窗口及限额须由运维核实。|
|计量与审计|Agent A 请求前复核 R01，记录请求、响应、用量和拒绝码；输入输出分别计量，未计量或无响应不可作零消耗。合成探针独立输出逐次诊断日志，只含阶段、状态及数字，不输出请求/响应正文或密钥，不创建真实调查审计。|

## 本机配置（在 backend 目录）

保留已有 .env.p31b；新环境才运行 bash scripts/p31b_env.sh init。使用本机受信编辑器编辑，权限 600，禁用云同步、shell 跟踪和明文备份。不要在聊天、命令行、截图或工单填入密钥。不要输出完整 docker compose config、docker inspect 或环境变量。

|变量|默认及填写要求|
|---|---|
|BUILDER_MODEL / BUILDER_BASE_URL / BUILDER_API_KEY|默认空；分别填写精确模型 ID、批准的基地址和网关专用密钥。|
|BUILDER_ALLOW_SYNTHETIC / BUILDER_ALLOW_ENTERPRISE|默认均 false；仅合成联调时前者 true，后者始终 false。|
|MODEL_OPS_TOKEN|运行时未设置即拒绝授权写入；新建环境生成独立随机值，已有环境由运维在本地通过密码管理器生成。不得与管理或只读令牌相同。|
|DOCUMENT_DISCOVERY_MODE / TENDER_MODEL_MODE / EVALUATION_MODEL_MODE|本轮全部 structural。无需开启文档发现、招标提取或参数评估的模型模式。|

1. 确认网关允许容器所在网络、DNS 及企业 CA，核实代理或 NO_PROXY 要求；不要关闭 TLS 校验。只允许 HTTPS 承载真实密钥。如需额外 CA 或代理配置，先由企业网络运维确认，不能从容器健康推断网关可达。
2. 编辑完成后按本轮镜像标签重新创建应用容器，而非仅 restart。在 backend 中执行：

~~~sh
P31B_IMAGE_TAG=f90ac6e docker compose --env-file .env.p31b -f docker-compose.p31b.yml config -q
P31B_IMAGE_TAG=f90ac6e docker compose --env-file .env.p31b -f docker-compose.p31b.yml up -d --no-deps --no-build --wait api builder worker indexer retrieval taskworker frontend
~~~

3. 运维从回环 API 使用 R01：POST /api/v1/admin/model-authorizations，必须同时提供管理员 Bearer 和 X-Model-Ops-Token。使用本机受信 HTTP 客户端的秘密变量，不将 header 放入 shell 历史；JSON 字段为 data_classification、approval_reference、approved_scope、expires_at（带时区的未来时间）。模型和端点由 API 从当前配置绑定；核对返回的完整端点、模型、范围、到期时间。先为 synthetic_public 登记真实的合成测试许可。不得自行编造依据或变更业务分类。普通管理员页面仅展示状态，不能批准。
4. 从 builder 容器运行固定输入探针：docker exec product-knowledge-p31b-builder-1 python -m app.agents.gateway_probe。它不接收文件、提示词或快照 ID；每一个请求前复核 synthetic_public 授权，分开验证文本、严格 JSON Schema、具名函数与参数、实际 token 字段；首个失败即停止，后续项目属于未测试。将脱敏输出存入本地验收日志。遇到 401/403 核实凭证权限，404 核实基路径与模型，400/422 核对扩展参数；不能为了通过而改用真实资料。合成通过不代替 Agent A 全流程或企业审批。
5. 企业授权须另行登记 enterprise、真实审批依据、批准的资料与用途及到期时间。先保留企业开关关闭，核对记录；生产审批范围必须覆盖预期调查。R01 按模型/端点/分类/到期时间检查，不自动解释范围中的自然语言。只有另行获准启动时才开启运行时开关，本轮到此停止。撤销用 POST /api/v1/admin/model-authorizations/{id}/revoke，随后核实管理员视图；撤销阻止下一请求，不追回已发出的请求。
