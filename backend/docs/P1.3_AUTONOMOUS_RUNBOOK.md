# Agent A自主源码探索运行说明

## 入口与兼容

先完成源码静态索引，管理员调用：
POST /api/v1/snapshots/{snapshot_id}/investigate

请求示例：
`{"module_ids":["已检索到的模块ID"],"investigation_mode":"autonomous","exploration_max_fragments":3,"include_equivalence":true}`

autonomous是新显式模式；不需要指定源码文件、行号或能力名。
bounded与explore请求兼容保留，旧默认explore不更改，推荐新建设使用autonomous。
原capability_limit只用于bounded；自主模式用exploration_max_fragments（默认6，上限12），不是能力数保证。

## 调查方式

1. 从索引提取模块入口、函数/方法/类符号、配置和未解释行范围；按定位生成100行以内窗口。
   并非只取前几个文件或文件开头；过长函数分片，所有分片仍有不完整语义风险。
   每类元数据最多1000条、队列最多256片段，超出显式保留deferred与inventory_truncated。
2. 同快照文档最多5个分段作为不可信业务线索；模型规划优先级和搜索词，
   文档截断单独标记，不将文档主张当事实或源码证据。
   首次规划同时携带一个高优先级、已完整回读片段，允许initial_result复用bounded保存首条观察/候选，
   减少一次独立模型往返；模型不提供initial_result时仍按普通队列执行，不伪造分析。
   规划前先复用同任务其他模块已完成片段，避免初始片段路径重复调用模型。
3. 服务端按优先级顺序取片段，调用共享read_source后由Pydantic AI微任务
   finish_fragment选择一条直接能力与精确行号，或candidate=null记录无新增发现。
   有候选时复用bounded的candidate_output：精确回读→证据登记→候选和片段检查点同事务。
4. 模型反馈follow_symbols/search_queries，服务端共享search_symbols/search_code_batch检索真实定位，
   再结合CodeEdge语法引用和find_references扩展。限定同快照、敏感文件过滤、无Shell和任意网络。
   每轮最多两个新搜索；其他请求入deferred。语法名称引用不能证明动态调用语义。
5. 检查点键包括file ID、原始哈希和行区间。相同/包含/重叠区间不重复分析已完成行。
   同任务其他模块调查若已经完成相同片段，可以复用且记录来源调查ID，不重复调用模型。
   已分析但无候选也保存检查点；失败后retry不重跑规划或成功片段。
6. 双侧等效调查再次精确回读实际候选证据，比较输入、输出、条件、异常和副作用，
   可记录not_equivalent或insufficient_evidence，不强迫生成关系。
   possible_equivalent必须有不同函数或模块的源码定位，仍仅hypothesis，不自动合并发布。
   本版只比较当前调查最近两条候选，不是全项目等效关系穷举。
   旧bounded后置等效入口也改用这一证据比较器；原explore仍是兼容路径，不作为本轮自主调度验收入口。

## 预算和未完成状态

沿用8请求/30工具/30000Token/80000上下文字符、4000单响应Token、60秒请求、180秒模块限制。
自主模式将请求/工具/Token/上下文限制同时应用于整任务，防止多个模块放大总预算。
任务时间从首次worker启动累计180秒，retry不重置，等待重试的时间也保守计入；
失败恢复不是免费增加预算，时间耗尽时需人工审查后创建新任务。
每次网络请求前检查预算；响应Token在收到后完整计量，不能保证单响应不超额。
180秒总时限同时约束每次微任务，包括输出校验重试。

预算、片段数或时间耗尽标partial；成功片段与候选不丢失，pending/deferred原样保留。
GET /jobs/{job_id}/investigations 的metrics.exploration含：
- tasks：定位、哈希、priority、reasons、pending/done、模型观察、扩展反馈、复用来源。
- searches/deferred：已执行检索、截断/未执行线索及游标。
- entrypoints：仍未解释的索引入口；仅阅读函数不会自动把入口解释为产品已支持。
- coverage：已知片段、已分析片段/文件、pending及未解释入口数，语义覆盖unknown。
- equivalence：双方证据定位、契约比较、反例/假设和缺口。
- stop_reason：实际停止原因。

即使已知队列用尽，knowledge_build_complete=false且coverage_incomplete=true；
局部队列处理成功不等于全项目能力完整、没有遗漏或已批准。
没有模型候选也不能据此证明不支持。

## 权限、并发与资源

worker继续使用knowledge-builder-single-worker互斥锁和单任务顺序调用模型，无模型并发。
builder配额保持0.5CPU/1024MiB；retrieval独立1CPU/768MiB；全部服务合计4CPU/6144MiB不变。
这只表示面向4C8G目标的资源约束；没有替代独立4C8G主机或企业规模实测。

企业外发仍false，worker重新读取源码和全部文档最高敏感分类，不能用请求标签降级。
公开例外仅两个随代码审阅的精确人工manifest，源码集合、实际文件与文档哈希均核验；
未知源码/手册、修改样例均拒绝。新样例manifest不包含gold文件。
所有原始候选、Evidence和关系保持unverified/hypothesis；不审批、不发布。
