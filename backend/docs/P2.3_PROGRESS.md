## 一、完成内容

### 1. 后端工作台 API

新增 `app/workbench/` 模块，并在 `app/main.py` 注册路由，前缀为 `/api/v1/tender/workbench`：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/tasks` | 当前用户任务列表，支持状态、品类、分页筛选 |
| GET | `/tasks/{job_id}` | 任务详情与复核汇总 |
| GET | `/tasks/{job_id}/results` | 逐参数结论、原子子要求、证据、人工复核与导出状态 |
| GET | `/tasks/{job_id}/parameters/{parameter_id}/reviews` | 参数复核历史，倒序 |
| POST | `/tasks/{job_id}/parameters/{parameter_id}/review` | 追加一条人工复核记录 |
| GET | `/tasks/{job_id}/exports` | 任务的导出产物列表 |
| POST | `/tasks/{job_id}/exports` | 创建 Word 或 Excel 导出任务 |
| GET | `/exports/{export_id}` | 导出任务详情 |
| POST | `/exports/{export_id}/download-token` | 重新签发短期下载凭证 |
| GET | `/exports/{export_id}/download` | 凭 `X-Export-Token` 请求头下载已生成文件 |

所有接口复用现有 Bearer Token 身份，不新建认证体系。任务、结果、复核与导出均按任务所有者隔离；其他用户及管理员访问统一返回 404，不泄露任务是否存在。

### 2. 数据库与迁移

新增两张表，迁移版本 `0011`，`down_revision = "0010"`：

- `evaluation_reviews`：人工复核只追加记录。保存自动结论副本、人工应答、动作、复核状态、是否认可、是否需重评、意见、调整理由、复核人、时间与关联 ID。
- `evaluation_export_jobs`：导出任务。保存格式、状态、文件名、存储键、大小、参数/原子/证据/复核计数、摘要、错误码、下载令牌与所属用户。

`0011` 可回退到 `0010` 后重新升级。未修改 P1.1～P2.2 的任何历史迁移；P2.2 的 `parameter_evaluations`、`atomic_evaluations`、`evaluation_evidence` 不被人工复核更新或覆盖。

### 3. 人工复核

- 四种动作：认可、人工调整、驳回、需重评。
- 每次提交新增一行复核记录，不更新旧记录，也不更新 P2.2 自动评估行。
- 最新复核按 `created_at, id` 升序迭代，末条为当前有效记录；历史记录仍可追溯。
- 自动结论与人工应答分列保存。调整动作必须给出不同结论与调整理由；与自动结论相同的“调整”返回 `REVIEW_VERDICT_UNCHANGED`。
- 复核汇总返回已复核、待复核、认可、调整、驳回、需重评数量及人工应答分布。
- 页面明确提示“人工复核记录已保存；系统自动结论与证据未改变。”

### 4. 结果与证据上下文

- 结果页只读取任务创建时固定的 `publication_id` 与发布哈希，不回退到当前生效版本。
- 证据展示来源类型、来源文件、位置、支持范围、适用条件与限制。
- 固定发布缺失、能力修订缺失或发布内容被篡改时，证据标为“来源不可用”；导出失败关闭，返回 `EXPORT_EVIDENCE_CONTEXT_UNAVAILABLE`，不生成编造证据的文件。
- “无法确认”保持原结论，不因人工复核自动改为“支持”。

### 5. 导出

导出以 P2.2 已持久化结果和任务固定发布快照为唯一数据源，并与结果页共用同一聚合逻辑。

- Word：可编辑段落与表格，不是图片；包含概览、逐参数结论、原子子要求、人工复核分列、证据附录与数据摘要。
- Excel：四张工作表——评估结果汇总、原子子要求明细、待确认与问题清单、证据索引。
- 公式注入防护：以 `= + - @` 或制表/回车开头的文本统一加前缀单引号，写入后保持文本类型；打开文件不执行来源宏或公式。
- 单元格控制字符清理、长度截断与证据数量上限。
- 不导出投标证明材料要求、未审核草稿、其他用户或品类数据、产品源码全文；证据仅导出已核验原文节选与定位。
- 下载同时校验登录身份、导出任务所属用户与短期下载令牌；错误令牌返回 403，未登录返回 401，未完成任务返回 409。
- 导出产物持久化到受控目录，数据库记录状态与摘要；重复下载不重新生成。

### 6. 前端工作台

仓库原先没有前端，本阶段在 `backend/frontend` 新建 React 19 + TypeScript + Vite 单页应用，使用 hash 路由，不引入第三方路由或 UI 库。

页面：

- 登录：粘贴普通用户令牌，保存到 `localStorage`。
- 任务列表：状态、品类、结论计数、复核进度、创建时间。
- 新建评估：选择品类，上传 DOCX/PDF/XLSX，确认提取结果后启动评估。
- 提取确认：参数、原子子要求与原文位置。
- 评估进度：轮询任务状态，完成后进入结果页。
- 评估结果：概览、复核进度、筛选、折叠参数、原子证据、来源文件、限制、人工复核弹窗、导出与下载。

前端未增加源码或产品文档上传入口，普通用户只选择产品品类，不选择版本。

### 7. 跨域支持

为支持独立部署的前端联调，新增最小的 CORS 配置：

- `Settings.cors_origins`，默认 `http://localhost:5173,http://127.0.0.1:5173`
- `Settings.cors_origin_list`，按逗号拆分并去空
- `create_app()` 仅在列表非空时注册 `CORSMiddleware`
- `allow_credentials=False`；允许 `Authorization`、`Content-Type`、`Idempotency-Key`、`X-Export-Token`
- 暴露 `Content-Disposition`、`X-Correlation-ID`

该改动只解决浏览器跨域预检，不改变认证与授权模型。生产建议同源反向代理，并按实际域名收紧或关闭 `CORS_ORIGINS`。

- 整改基线：`210967a`

### 1. R01 提取页人工修正

- 复用 P2.1 修正能力，新增只读 `GET /api/v1/tender/extractions/{job_id}/corrections`。
- 支持修改名称/正文、拆分、合并、新增遗漏参数、确认。
- 修正后写 `anchor_status` 与 `original_locator`；新增参数统一重排，消除 `1000015` 序号。
- 前端展示修正前/后，保存后重新拉取服务端结果；页面提示会影响后续 P2.2 评估，历史结论不自动更新。
- 修正动作、修正前后内容、操作人与时间进入不可变审计。

### 2. R02 下载凭证

- 迁移 `0012_export_integrity.py` 新增 `download_expires_at`、`file_sha256`。
- 下载凭证默认 3600 秒到期；过期返回 `EXPORT_TOKEN_EXPIRED`。
- 新增 `POST /exports/{export_id}/download-token` 重新签发；仍校验身份、任务归属与导出状态。
- 令牌只通过 `X-Export-Token` 请求头传递，不再进入 URL；审计仅记录令牌指纹。
- 旧导出缺少完整性摘要时返回 `EXPORT_INTEGRITY_UNAVAILABLE`，要求重新生成。
- 下载前重新计算文件 SHA-256；文件被替换或丢失分别失败关闭。
- 联调发现 CORS 允许头缺少 `X-Export-Token`，已在 `app/main.py` 修复并强化断言。

### 3. R03 导出前固定发布再验证

- 导出固定使用任务的 `publication_id` 与发布哈希，不回退当前版本。
- 新增 `verify_export_evidence()`，在生成文件前回读并比对证据 ID、来源引用、定位、来源哈希、引文哈希与能力修订归属。
- 原始文件修改/丢失、文档分段改变、发布篡改、导出文件替换均失败关闭。
- 不修改已持久化自动结论与证据行。

### 4. 前端凭证安全

- 登出与 401 均清除 `localStorage` 访问令牌。
- 访问令牌仅用于 `Authorization`，下载凭证仅用于 `X-Export-Token`，不写日志、不拼 URL。
- 不使用 `dangerouslySetInnerHTML` 或 `innerHTML`。
- 仍为令牌粘贴登录，未实现企业 SSO，但保留凭证注入/清除边界。
