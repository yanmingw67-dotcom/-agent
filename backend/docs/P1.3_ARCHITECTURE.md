# P1.3 架构与保守边界

## 存储与业务路径

新增迁移0005：module_investigations、evidence、capability_claims、claim_evidence_links、
capability_relations、investigation_traces。旧表字段/索引/现有路由保持兼容。
源码导入/索引仍沿原流程；管理员新建knowledge_build任务经原durable outbox投递builder队列。
任务内按模块串行处理，成功模块独立提交，下一模块失败不抹掉前面成果。
证据可先登记并留下未引用记录，能力/链接/关系与模块完成状态同一事务原子写入；
不把半份能力作为成功检查点。重复消息和成功模块重试不重复执行；其他模块/尝试留审计。
任务token和状态在写入前锁内复验，过期处理器不允许提交；快照已发布禁止修改。

所有模型输出经Pydantic强类型校验、当前模块/快照/本次登记证据集合核验、证据再次回读验证。
模型不能产生verified/approved，DB也限制候选状态和hypothesis关系。
本批语义验证始终unverified，不提供“已验证产品能力”或审核白名单假入口。
关系仅同模块输出局部key引用，保存真实能力ID；不实现跨模块归并或自动等效认定。

## 只读工具与证据

服务端冻结RunContext，模型请求中没有可改品类/快照/根路径/任意命令。
重用P1.2 ReadOnlyTools；模型专用envelope只去掉null冗余字段，
保留truncated、coverage_incomplete、next_cursor、unresolved，HTTP原接口响应不改变。
可恢复404/422定位错误转ModelRetry并带稳定错误码；权限/哈希变化/预算等继续终止。
来源登记先要求准确回读，之后重新核对文件/分段/原始文档哈希和精确范围。
证据ID=同快照、来源、定位、原始哈希、引用哈希的确定性SHA256，重复登记不多插。
不保存虚构证据；源码权限/DLP策略在所有回读前执行。
source_verified只代表来源真实，模型语义和运行时可达性仍待核验；
测试文件或仅文档证据强制保守降级，不向“已验证”提升。

## 模型与计量

锁定pydantic-ai-slim[openai]及Pydantic明确版本。Pydantic AI Model可替换，
当前显式适配OpenAI兼容企业网关；无硬编码模型供应商或宿主凭据。
模型API Key只存本地.env，builder读取，其他服务不注入该Key。
人工和企业数据外发分别开关，默认都false；管理员可信声明不是自动DLP证明。

审计模型包装记录每次请求、响应Token、工具名称、ID哈希及结果哈希/长度/完整性，
不保存完整消息、推理过程或敏感源码。能力草稿只允许管理员读取。
工具/模型请求预算和用量在模块检查点累积，显式retry不重置；
SDK不隐式重试，模型输出/工具定位恢复受Pydantic AI与累计请求预算约束。
计价仅可用配置费率估算，不是供应商账单；无费率或不完整用量时保持null。
模块时间和任务RQ时间独立约束；Token为响应后检查，存在单次响应超额可能，已明确披露。

## 七服务资源

|服务|CPU上限|内存MiB|
|---|---:|---:|
|api|0.5|512|
|worker|0.25|768|
|indexer|0.75|1280|
|builder|0.5|1024|
|retrieval|1|768|
|postgres|0.75|1536|
|redis|0.25|256|
|总计|4|6144|

builder与indexer独立全局Redis互斥，默认各一次只执行一项任务；
builder根文件系统只读、非root、只挂载只读源码/文档，不挂原始归档/控制卷。
retrieval不注册新候选写业务路由，保留原DB默认只读事务。
总配额实验不能替代独立4C8G VM复验。大量日志/数据库增长仍需部署方监控；
本批不实现自动清理、企业账号/TLS体系、OCR或大文件内容索引。
