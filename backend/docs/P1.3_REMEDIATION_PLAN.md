# P1.3整改计划与事前验收门槛

基线9d91986；仅修改P1.3，不进入P1.4，不默认推送。原138项测试、0001～0005和历史日志不改。
优先级：可信分类→真实单候选闭环→多候选/等效假设→完整回归与报告。

## 设计

普通上传和历史来源默认enterprise；snapshot/document持久化分类。
调查请求旧data_classification兼容保留，仅审计，不授予降级权。
worker从数据库重新读取来源，以同快照源码和全部文档最高敏感级别决定外发。
专用admin approve-public-fixture只接受随代码审查的人工样例精确文件清单/哈希，
再次回读文件并核对，任意修改、额外文件或未知文档一律不能标public；写管理员审计。
这不是任意企业审批/发布平台。

新增bounded有限调查模式：每条候选为独立紧凑模型工具输出；
共享read_source读取有限片段→真实模型选择机制/限制与行范围→
服务端精确回读→register_evidence重验→候选/链接事务检查点。
不把源码里的指令当命令、不执行源码。每条先保存，后续超时不抹掉。
旧explore路径保留兼容既有接口/测试；本轮真实验收一律显式bounded。
不以FunctionModel或预置草稿作为真实效果验收；模拟仅用新增故障回归。

## 事前门槛（运行后不修改）

1. 最小冒烟：同一notify人工模块，单次有界任务，至少1个真实模型候选，
   Evidence/Claim/Link均存在，API重新回读哈希一致；候选限制非空、语义unverified。
   工具终端输出经Pydantic校验，非文本手工填入数据库。
2. 先通过1，再重复单候选冒烟一次以报告2次实际成功率，而非声称统计稳定性。
3. 多能力：同一notify模块最多3候选，至少2条不同action/name，逐条有来源证据和限制；
   技术等效独立后续步骤，只有hypothesis，不阻断前面的持久化。
4. 负例：不得把固定平台URL和平台JSON格式推为任意URL/自定义认证通用Webhook；
   不得从未接入重试或仅测试代码认定产品支持。人工复核真实输出，并列误判和不确定项。
5. 后续可测events/http/tests，未调查模块不计漏报；
   不要求全15机制才能通过本批最小闭环，未运行部分如实标记。
6. 请求/Token/工具/模块时间仍有界，无隐式供应商切换；
   实测模型/Token/耗时/费用未知状态及脱敏轨迹逐轮归档。
7. 原138项全部通过，新增企业降级、混入企业文档、公开样例篡改、
   首条保存后模型超时/恢复不重复、模型不可用失败等回归通过。
8. 独立4C8G和企业规模本轮不冒称验证；密钥字节扫描无命中。

本轮有限模式先用既有模型low档、4000单响应/30000模块Token、60秒请求上限；
优先缩小schema/payload与轮次，不用粗暴增加预算求成功。失败需诊断，不盲目重跑。
