# P11-004 / P11-005 运维与恢复整改计划

## 当前明确边界

P11-004 尚未实现全局硬配额、自动回收或清理 API。单上传/单文件/总展开与
容器内存/CPU/时间限额已存在，但不能阻止长期累积占满卷。
本次不以未经验证的自动删除功能解决磁盘问题，不删除任何原始归档或已发布证据。
P1.1 仅允许受控试运行；正式 P1 发布前必须完成以下门槛。

## 可立即执行的运维策略

- 分别监控 Docker 数据卷所在文件系统和本机开发 storage 所在文件系统。
- 使用率 >=70%：预警并评估容量；>=80%：暂停管理员导入，先备份并人工盘点；
  >=90% 或可用空间不足“单次最坏导入 600 MiB × 并发数 + 1 GiB 保留空间”：严重告警。
- 指标检查间隔建议 1 分钟，由部署平台执行；告警接收人必须为明确的运维值班人。
  本项目当前没有自动告警发送器，上述阈值不是已实现的应用硬限制。
- 进入清理流程前停止新增导入、确认在途任务、导出数据库与卷清单；不能按文件 mtime
  直接删除 UUID 目录，也不能用 docker compose down -v 充当清理工具。
- 所有删除均需管理员明确确认，保留被删除资源 ID、审批与备份记录。

## 分批实现节点

|节点|必须实现/验收|
|---|---|
|P1.2 导入规模扩大前|存储预留/硬配额，处理跨进程并发预留和失败释放；容量不足明确拒绝新导入|
|P1.2|只读孤儿扫描报告，按数据库归档引用和 manifest 关联，提供 dry-run；不得直接删除|
|P1.4 发布前|保留策略及人工批准清理：保护 active_snapshot、在途任务、审核引用和证据引用；事务锁内复验|
|P1.5 发布阻断验收|磁盘临界值、并发预留、失败归档、崩溃临时目录、历史证据保留和恢复专项测试|

建议默认保留（须由管理员确认）：生效快照及被证据引用快照无限期保留；
失败输入归档至少 30 天；孤儿临时目录至少 7 天并确认无在途任务后才进入待审批清单。
所有保留天数均是规划，不是已自动执行的清理行为。

## 本次 P11-005 已覆盖

- Queue 测试替身：独立数据库会话能在 enqueue 返回前看见已提交 token，立即执行成功。
- 认领后未投递退出；投递后未确认退出；相同消息 ID 重投；重复处理只保留一份 manifest。
- 提取目录已提交、任务结果未提交退出：失联记录、显式 retry 后核对哈希并复用同一快照。
- 数据库提交前故障注入不投递，Redis 响应丢失重投、Redis 不可达后的恢复。
- 真实 PostgreSQL/Redis/RQ：立即消费、重复真实消息、并发同品类上传 202/409。
- 四服务运行及重启持久化结果以 reports/remediation 实际日志为准，不以前述本机测试代替。

未完成专项：真实网络层 PostgreSQL 事务 COMMIT 响应丢失、多实例长时间高并发、
磁盘写满和断电恢复、真实 OS 强杀所有崩溃点。后续在发布前按故障矩阵补齐；
不能把受控异常注入等同于已真实复现所有进程/网络故障。
