# P1.5 只读 Knowledge Probe 架构与边界

基线：`f2a43329ef353ebef13747ca0ea0a8d5219bae72`（P1.4 验收基线）。
依据：原设计书 §9 Probe 契约、§11 AC-14/AC-16、§12 P1.5。
本文件只描述 P1.5 已实现范围；不包含 Agent B、自动审核、模型调用或写入接口。

## 1. 不变量

1. Probe 只读：不创建、修改、删除任何品类、快照、修订、发布、证据或任务记录。
2. Probe 只读取品类当前生效发布清单，不接受调用方指定快照、版本或发布 ID。
3. Probe 不调用模型，不做满足/不满足、合规或等效性结论。
4. 检索服务不加载审核、上传、发布、回滚等写路由；后台 API 不执行 Probe。
5. 发现指针、清单哈希、修订新鲜度或证据校验异常时 fail closed：返回结构化缺口，
   不把不完整内容包装成完整结果。

## 2. 组件与数据流

```text
调用方
  -> POST :8001/api/v1/probes（Bearer read/admin）
     -> retrieval 服务（SERVICE_MODE=retrieval）
        -> 每请求独立数据库连接
           -> SET TRANSACTION ISOLATION LEVEL REPEATABLE READ READ ONLY
           -> categories.active_publication_id / active_snapshot_id
           -> publications.payload_json + payload_hash
           -> claim_revisions（同快照、最新编号）
           -> evidence 登记 -> 只读源码/文档卷复验
        -> 确定性词法匹配 + 有界组装
     -> 响应（Cache-Control: no-store）
```

- 后台 API（8000）保留管理接口；其 `POST /api/v1/probes` 返回
  `503 PROBE_RETRIEVAL_SERVICE_REQUIRED`。
- 检索服务（8001）不注册写路由；管理路由在其进程中返回 404。
- 源码卷与文档卷均以只读方式挂载；容器保持只读根文件系统、丢弃全部 capability、
  `no-new-privileges` 与 pids 限制。

## 3. 一致性模型

每个请求在独立连接上开启 PostgreSQL `REPEATABLE READ READ ONLY` 事务，并在该事务内读取：

1. 品类当前发布指针与快照指针；
2. 发布清单、清单哈希与快照作用域；
3. 清单中修订的最新编号；
4. 证据记录与只读来源文件。

同一请求不会混读切换前后的发布；发布切换只在下一个请求生效。Probe 不为读取加品类写锁，
因此不会阻塞正常的发布/回滚写入。回滚到旧发布时，只要清单与证据仍有效，响应可精确复原
（验收比较时忽略 `duration_ms` 这一非语义字段）。

真实 PostgreSQL 测试使用独立 schema，覆盖发布切换期间的单请求快照、只读事务拒绝写入、
陈旧指针、并发审核与回滚等场景。SQLite 仅用于普通单元/集成测试，不作为一致性结论依据。

## 4. 校验与降级

| 条件 | 行为 | 稳定标识/结果 |
|---|---|---|
| 未发布/无生效清单 | 拒绝读取，不推断不支持 | 409 `KNOWLEDGE_NOT_PUBLISHED` |
| 生效指针/快照状态不一致 | fail closed | 409 `PUBLICATION_POINTER_INVALID` |
| 清单哈希不一致 | fail closed | 409 `PUBLICATION_TAMPERED` |
| 清单作用域不一致 | fail closed | 409 `PUBLICATION_SCOPE_INVALID` |
| 清单中修订已失效/不匹配 | 跳过该能力并返回缺口 | `PUBLICATION_REVISION_INVALID` |
| 存在更新但未发布的审核 | 隐藏旧修订并返回缺口 | `NEWER_REVIEW_NOT_PUBLISHED` |
| 证据来源缺失/哈希不符 | 跳过相关能力/关系并返回缺口 | `EVIDENCE_SOURCE_UNAVAILABLE` 等 |
| 关系校验失败 | 跳过关系并返回缺口 | `RELATION_REVIEW_INVALID` |
| 无词法命中 | 返回空候选和缺口，不表示不支持 | `status=no_match` |
| 空知识库 | 返回空结果和缺口 | `status=knowledge_empty` |
| 输出/证据/清单超限 | 明确 `truncated` 或 413，不静默裁掉边界 | `PROBE_RESULT_LIMIT` / `PROBE_RESPONSE_LIMIT` |
| 调用后台 API | 拒绝执行 | 503 `PROBE_RETRIEVAL_SERVICE_REQUIRED` |
| 匿名/错误令牌 | 拒绝 | 401 |
| 未知品类 | 拒绝 | 404 `CATEGORY_NOT_FOUND` |
| 额外字段/查询参数/越界 limit/空白输入 | 严格拒绝 | 422 |

Probe 的响应包含 `unverified_gaps` 和固定的 `warnings`；即使没有命中，也明确
`no_match_does_not_mean_unsupported` 与 `coverage_gaps_do_not_mean_unsupported`。
`formal_compliance_decision` 恒为 `null`，`support_status` 恒为 `not_assessed`，
`consistency` 为 `request_start_publication`。

## 5. 安全边界

- 身份：只接受 `read` 或 `admin` 角色；匿名与错误令牌均为 401。
- 证据回读：显式携带 `snapshot_id` 复读后台快照需要 admin；read 令牌不可选择后台快照，
  返回 403。不传 `snapshot_id` 时，read/admin 均可读取当前生效发布的证据。
- 输入：`ProbeRequest` 设置 `extra=forbid`；查询参数一律 422；`category_id`、
  `requirement_text` 去除首尾空白并拒绝纯空白；`limit` 限制为 1–20。
- 只读：数据库事务只读；检索服务无写路由；不提供源码下载静态入口。
- 资源：单请求独立连接；清单最多 100 个能力、4 MiB；证据最多 100 条；
  完整响应最多 128 KiB；检索超时使用 `SEARCH_TIMEOUT_SECONDS`；服务并发受限。
- 内容：源码与文档文本一律视为不可信数据；不执行源码、不拼接 Shell、不调用模型。
- 输出：`Cache-Control: no-store`；不返回符合性结论、模型草稿或未审核内容。

## 6. 性能与容量

P1.5 基线在 Docker Compose cgroup 配额下测得，不是独立 4C8G 虚拟机：

| 服务 | CPU | 内存 |
|---|---:|---:|
| api | 0.5 | 512 MiB |
| retrieval | 1.0 | 768 MiB |
| builder | 0.5 | 1024 MiB |
| postgres | 0.75 | 1536 MiB |

实测 Probe 在空闲、合成 Builder 负载和 FunctionModel 驱动的真实 Agent A 运行时下
均无错误；详见 `P1.5_ACCEPTANCE_REPORT.md` 与 `reports/p15/`。公开小样例的延迟
不能外推为企业规模或独立虚拟机性能。

## 7. 未包含

- Agent B、自动能力合并、自动审核或自动发布；
- 语义检索/向量索引、模型判定合规；
- 企业真实源码、真实企业数据或真实模型能力验收；
- 独立 4C8G 虚拟机性能结论。
