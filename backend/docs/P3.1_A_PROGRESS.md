## 一、目标与结论

P3.1-A 将原先只能通过管理员 API 完成的产品知识维护流程，收敛为一个浏览器端工作台：管理员可完成受控源码上传、索引、文档暂存与上传/替换/重解析/删除、候选审核、证据登记、发布前检查、发布、回滚与审计查看。

结论：

1. 工作台已经走通“上传合成源码 → 派生文档暂存 → 上传合成 DOCX → 结构化文档发现 → 逐字段证据审核 → 发布 → 回滚与审计”的完整链路。
2. 发布仍由既有 `publisher.publish` / `publisher.rollback` 完成；前端不能直接修改 `active_snapshot_id`、`active_publication_id` 或发布清单。
3. 管理员与普通售前在服务端严格分离：普通用户访问管理员接口返回 403，未登录返回 401。
4. “只有正式技术文档、没有源码”的品类当前**不能建库**；系统不会伪造源码快照。这是本轮明确保留的限制，不是未完成的界面功能。
5. 本轮没有新增数据表或迁移；管理员接口只是既有服务的只读聚合与写操作复用。

## 二、管理员 API

新增 `app/api/admin.py`，并在 `app/main.py` 中以 `/api/v1` 前缀注册，仅在非 retrieval 服务模式生效。除 `/auth/me` 使用 `current_identity` 返回身份外，所有 `/admin/*` 接口使用 `Depends(admin)`，普通用户无法通过前端或请求头绕过。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/auth/me` | 返回当前身份、role、is_admin、静态令牌模式与 SSO 预留标志 |
| GET | `/admin/overview` | 品类总览、待审数量、失败任务、最近任务/发布、模型授权状态、文档类型与建库限制 |
| GET | `/admin/categories` | 品类列表（同一聚合的列表视图） |
| GET | `/admin/jobs` | 按品类、状态、任务类型分页查询任务 |
| GET | `/admin/categories/{id}` | 工作区聚合：工作快照、文档、审核汇总、生效发布、发现运行、能力开关 |
| GET | `/admin/snapshots/{id}/review-queue` | 审核队列、最新修订、门槛错误、已接受修订 ID |
| GET | `/admin/snapshots/{id}/release-check` | 发布前检查：可发布性、已接受修订、逐能力阻断项、是否已在清单 |
| GET | `/admin/documents/{id}` | 单文档详情与解析状态 |
| GET | `/admin/audit` | 按品类、动作、操作者分页查询审计事件 |

复用而非重写的写操作：

- `POST /categories/{id}/documents`：管理员技术文档上传（Document/DocumentSegment）。
- `POST /snapshots/{id}/documents/{document_id}/replace`：同类型替换，新文件新存储键，不覆盖历史。
- `POST /snapshots/{id}/documents/{document_id}/reparse`：本轮新增，仅派生暂存快照内允许，引用了证据的文档被拒绝。
- `DELETE /snapshots/{id}/documents/{document_id}`：仅暂存快照，已发布快照拒绝。
- `POST /snapshots/{id}/discover-documents`：文档独立发现，只产生候选。
- `POST /capabilities/{id}/validate`、`/review`、`/merge`、`/capability-relations/review`：门槛校验与人工审核。
- `POST /snapshots/{id}/review-evidence`：登记证据。
- `POST /snapshots/{id}/publish`、`POST /categories/{id}/rollback`：复用既有发布器。

## 三、文档暂存与源码回退

### 1. 派生暂存快照

`document_staging.staging()` 保持原有要求：快照必须为 `extracted`，且品类没有在途任务。派生快照的 `derivation_type=document_update`，不修改源快照或已发布快照。

### 2. 无生效发布时的源码定位

`document_staging._source_snapshot()` 增加回退：品类没有 `active_snapshot_id` 时，取该品类最近一次同时满足以下条件的快照：

- `status=extracted`
- `index_status=indexed`
- `derivation_type IS NULL`

这样可以在首次发布前从已索引源码派生文档暂存，同时仍然要求真实存在已索引源码；不会创建空源码或伪造 manifest。若没有满足条件的源码快照，接口返回明确阻断信息。

### 3. 文档变更边界

- 管理员浏览器入口仅支持 DOCX/PDF/XLSX 技术文档；服务端复核扩展名、MIME 与文件签名（后端内部路径仍保留 `.md/.txt`，见限制 2）。
- 超大文件返回 413 `DOCUMENT_TOO_LARGE`；空文件返回 422 `EMPTY_DOCUMENT`。
- 同名文件不覆盖：生成新文档与新存储键，保留旧文档与旧哈希。
- 替换要求类型一致，否则 422 `DOCUMENT_REPLACE_TYPE_MISMATCH`。
- 已发布快照禁止原位替换/删除/重解析，返回 `DOCUMENT_STAGING_REQUIRED`。
- 文档被审核证据引用后，删除/替换/重解析返回 `DOCUMENT_IN_USE`。
- 解析失败保留 `parse_status=failed` 与 `error_code`，不静默忽略。
- 重解析只清理并重建该文档的分段与派生索引，新建 `document_index` 任务，并写审计 `documents.staging.reparse_requested`。

## 四、审核、发布与审计

### 1. 审核

- 候选全部来自既有调查/文档发现；管理员必须逐字段绑定已登记证据、标记“证据支持”、填写核对说明。
- 接受修订必须携带 `human_confirmed=true`；服务端重新执行断言门槛、声明类型、依赖证据与冲突检查。
- 已接受修订不可变；修改会生成新修订号。

### 2. 发布前检查

`release-check` 返回：

- `publishable`：是否存在未发布的已接受修订，且无阻断项。
- `blocking`：逐能力门槛错误、未解决冲突、已发布状态等。
- `items[].published`：该修订是否已在当前生效发布清单。

发布后再次检查会返回 `publishable=false`，阻断项为 `NO_UNPUBLISHED_ACCEPTED_REVISION`。这是预期语义：发布器不会重复发布同一清单；页面不会提供绕过按钮。

### 3. 发布器

`publisher.publish` / `rollback` 保持既有约束：

- 发布前锁定品类/快照，校验期望生效发布 ID。
- 校验修订为最新人工接受版本，重新执行门槛与冲突检查。
- 校验覆盖缺口已显式确认。
- 证据回读失败时失败关闭。
- 清单写入不可变 `Publication`，同时切换品类两个指针并写 `PublicationSwitch`。

本轮只在 API 层补充审计：

- `publication.publish`：resource_id 为发布 ID，细节含 category_id、snapshot_id、payload_hash。
- `publication.rollback`：resource_id 为发布 ID，细节含 category_id、snapshot_id。

### 4. 审计查询

`/admin/audit` 支持按 `category_id` 过滤；`category_id` 的匹配集合包含 `Publication.id`，因此发布/回滚事件能按品类正确归集。审计只读，不提供删除或修改接口。

## 五、前端工作台

在既有 React 19 + TypeScript + Vite 应用中新增：

- `AdminOverview.tsx`：管理者概览、品类卡片、模型授权状态、限制说明、最近任务/发布。
- `AdminCategories.tsx`：品类列表。
- `AdminWorkspace.tsx`：五个标签页——概览与构建、技术文档、能力审核、发布与回滚、审计日志。
- `AdminReviewPanel.tsx`：审核队列、逐字段断言、证据检索/登记、门槛校验、接受/退回/拒绝。
- `api.ts`、`types.ts`、`hooks.ts`：管理员 API 客户端与类型。
- `Layout.tsx`、`App.tsx`：管理员入口与路由；普通用户不显示管理员导航。
- `styles.css`：管理员页面样式。

界面行为：

- 普通用户看不到管理员入口；即使手工输入管理路由，服务端仍返回 403。
- 文件选择器只接受 DOCX/PDF/XLSX；前端校验只是体验优化，服务端仍是权威校验。
- 文档面板提供“刷新文档”，用于解析任务完成后的状态更新；不依赖切换标签页。
- 发布按钮只在 release-check 返回 `publishable=true` 时可用；不可发布时只显示阻断原因。
- 回滚按钮不能选择当前生效发布；需要存在历史发布记录。回滚仍由服务端校验目标发布、清单哈希与证据回读。

## 七、已知限制与未完成事项

1. **仅文档建库不支持**：当前品类必须先有已索引受控源码。`GET /admin/overview` 的 `limits.document_only_build_supported=false` 与 `document_only_note` 明确返回该限制。不得通过伪造源码快照或复用招标参数上传 API 绕过。
2. **后端文档后缀比前端宽**：`DOCUMENT_SUFFIXES` 仍包含 `.md/.txt` 供内部/测试路径使用；管理员前端只放行 DOCX/PDF/XLSX。服务端对管理员上传仍执行扩展名白名单、MIME 与签名校验。若未来要求后端也严格只允许三类，需要单独评估对既有 P1.6 测试与内部导入的影响。
3. **worker 不在验收 API 容器内自动启动**：浏览器联调时需单独启动 ingestion/index/builder worker；验收容器未内置进程管理。
4. **验收容器目录不一致**：容器内 `SOURCE_ROOT=/p31data/sources` 与 `INGESTION_ROOT=/p31data/ingestion` 不一致，首次 source_index 失败 `INDEX_INTERNAL_ERROR`。已在容器内用软链修正；容器重建会丢失，属于环境配置问题。
5. **SSO 未接入**：当前为静态管理员/普通用户令牌，`/auth/me` 返回 `auth_mode=static_token`、`sso_ready=false`。权限判定集中在服务端，保留了替换身份来源的结构，但没有实现完整 SSO。
6. **本轮未做真实产品资料验收**：所有文档、源码与能力描述均为合成测试资产，不能据此宣称真实 WAF 能力通过。
7. **未进入 P3.2/P3.3**：本轮不包含真实招标参数评估、正式业务验收或生产上线。
