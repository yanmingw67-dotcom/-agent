# P3.1-A 管理员产品知识维护工作台 · 操作指南

- 适用对象：产品知识管理员
- 适用阶段：P3.1-A 管理员工作台
- 前置条件：后端已启动、管理员令牌有效、品类已存在、ingestion/index/builder worker 已运行
- 重要边界：本指南只说明管理员维护操作，不代表真实 WAF 产品能力已验收；不得上传未经授权的真实资料

## 一、进入工作台

1. 打开评估工作台地址，例如 `http://127.0.0.1:15173/`。
2. 在登录页粘贴**管理员令牌**。令牌只保存在当前浏览器的 `localStorage`（键名 `p23.workbench.token`），不会写入页面 URL 或验收日志。
3. 登录后顶部导航出现“管理员”入口；普通用户令牌不会显示该入口。
4. 进入“管理员概览”后，可看到品类数量、待审核数量、失败任务、最近发布与模型授权状态。

权限说明：

- 管理员接口全部由服务端校验，前端隐藏菜单不是安全边界。
- 普通用户即使手工输入 `/#/admin`，接口仍返回 403；未登录返回 401。
- 当前为静态令牌模式（`auth_mode=static_token`），尚未接入 SSO。

## 二、管理员概览

概览页用于判断“现在能不能维护、先处理什么”：

1. **品类卡片**：每个品类显示是否已有生效发布、待审核数、最近任务。
2. **待审核数量**：进入品类工作区后，在“能力审核”标签处理。
3. **失败任务**：先看错误码与阶段，再决定重建索引或重新上传，不要直接改数据库。
4. **模型授权**：展示服务端是否允许调用模型、文档发现模式；前端不能覆盖。
5. **建库限制**：`document_only_build_supported=false` 表示“只有技术文档、没有已索引源码”的品类不能建库。

点击品类卡片进入工作区。

## 三、工作区结构

品类工作区有五个标签：

| 标签 | 用途 |
| --- | --- |
| 概览与构建 | 选择工作快照、上传源码、构建/重建索引、派生文档暂存、发起能力调查 |
| 技术文档 | 上传、替换、重解析、删除暂存文档，查看解析状态与分段 |
| 能力审核 | 查看候选、登记证据、逐字段断言、门槛校验、接受/退回/拒绝 |
| 发布与回滚 | 发布前检查、发布当前清单、选择历史发布回滚 |
| 审计日志 | 按时间查看资料、文档、索引、审核、发布与回滚事件 |

页面上的“刷新”按钮只刷新工作区聚合；“技术文档”面板内的“刷新文档”用于解析任务完成后的文档状态更新。

## 四、上传受控源码并建立索引

源码是当前建库的基础。没有已索引源码时，不能派生文档暂存快照。

1. 在“概览与构建”找到“源码包”。
2. 选择受控源码 ZIP，点击“上传为新快照”。
3. 上传只创建待解压快照，**不会自动调用外部模型**。
4. 等待 ingestion worker 解压；快照状态变为 `extracted`。
5. 点击“构建 / 重建索引”，等待 index worker 完成。
6. 索引成功后，快照显示 `extracted/indexed`，才可以：
   - 派生文档暂存快照；
   - 发起能力调查（是否允许调用模型由服务端决定）。

注意事项：

- 不要上传未经授权的源码或真实产品资料。
- 上传文件名和路径由服务端处理，客户端不能指定存储路径。
- 索引失败时先看任务错误码；常见原因是对象存储根目录配置不一致或 worker 未运行。

## 五、派生文档暂存快照

文档修改不能直接发生在已发布快照上，必须先派生暂存快照。

1. 确认当前源码快照为 `extracted/indexed`。
2. 在“概览与构建”的“文档暂存”区域点击“派生文档暂存快照”。
3. 系统创建一个 `derivation_type=document_update` 的派生快照，并复制现有文档；不会修改源快照或生效发布。
4. 系统自动切换到该暂存快照，并进入“技术文档”标签。

如果没有生效发布，系统会回退到该品类最近一次满足 `status=extracted`、`index_status=indexed`、`derivation_type IS NULL` 的源码快照。该回退仍要求真实存在已索引源码，**不会伪造源码快照**。

## 六、技术文档维护

### 1. 上传

1. 确认当前快照为 `extracted + document_update`，页面显示“可编辑暂存”。
2. 在“技术文档”选择文件，点击“上传到暂存快照”。
3. 仅接受 DOCX / PDF / XLSX；服务端还会校验 MIME 与文件签名。
4. 上传返回 202 后，文档进入解析队列；解析完成后状态为 `parsed`，并显示分段数、解析器版本、SHA-256 与大小。
5. 若列表没有立即更新，点击“刷新文档”。

### 2. 同名文件

同名文件不会覆盖旧文件。每次上传都会生成新文档与新存储键，旧文档和旧哈希保留，便于审计与历史引用。

### 3. 替换

“替换”要求新文件与原文件类型一致：

- 类型不一致返回 `DOCUMENT_REPLACE_TYPE_MISMATCH`。
- 替换生成新的存储键与哈希，不覆盖历史文件。
- 已发布快照中的文档不能原位替换；已引用为审核证据的文档也不能替换。

### 4. 重解析

用于解析器升级、分段异常或文档内容未变但需要重建索引的场景：

- 只有派生暂存快照允许重解析。
- 已发布快照返回 `DOCUMENT_STAGING_REQUIRED`。
- 已被审核证据引用的文档返回 `DOCUMENT_IN_USE`。
- 重解析会重建该文档的分段与派生索引，并写审计 `documents.staging.reparse_requested`。

### 5. 删除

- 只有暂存快照允许删除。
- 已发布快照或已被证据引用的文档禁止删除。
- 删除前先确认该文档没有进入任何审核证据。

### 6. 解析失败

解析失败不会静默忽略：文档保留 `parse_status=failed` 与错误码。处理顺序：

1. 查看错误码与文件类型。
2. 确认文件未损坏、未加密、扩展名与实际格式一致。
3. 必要时替换文件或重新上传。
4. 不要通过改数据库把失败改成成功。

## 七、文档独立发现

文档发现用于从技术文档中提取候选能力，只产生候选，不直接发布。

1. 确认暂存快照已重建索引并达到 `extracted/indexed`。
2. 发起文档发现（`POST /snapshots/{id}/discover-documents`）。
3. 当前使用 `structural` 模式：不调用外部模型，按结构规则生成候选。
4. 发现完成后，“能力审核”队列出现候选；每个候选仍需人工逐字段审核。

注意：候选数量不等于已接受能力；未审核候选不会进入发布清单。

## 八、能力审核

### 1. 打开候选

在“能力审核”选择待审核候选。右侧显示断言字段、现有证据、门槛提示与审核操作。

### 2. 登记证据

1. 在证据检索区选择来源类型（源码或技术文档段落）。
2. 输入关键词检索，确认引文与上下文。
3. 点击登记证据；服务端会重新读取来源并校验哈希，不信任前端传入的摘录。
4. 登记后的证据可用于当前候选的字段断言。

### 3. 逐字段断言

对每个字段填写或确认：

- `name`、`action`、`target`、`business_goal`；
- `implementation_mechanism`、`supported_scope`、`limitations`；
- 选择对应证据；
- 标记语义结论（证据支持 / 证据不足 / 证据冲突等）；
- 填写人工核对说明；
- 勾选“已核对文档引文范围”。

要求：

- 每个断言必须绑定已登记证据，不能只写自然语言结论。
- 证据与描述不一致时，应标记冲突或不足，不能强行选择“证据支持”。
- 文档明确写出的内容与推断内容要区分，推断不能当作产品事实。

### 4. 可用性依据

选择“文档明示”“源码实现”等依据，并完成：

- 产品范围内确认；
- 已人工阅读全部证据与描述确认；
- 审核意见。

### 5. 校验门槛

点击“校验门槛”。服务端会重新执行：

- 断言字段完整性；
- 证据绑定与证据状态；
- 声明类型与依赖关系；
- 未解决冲突；
- 人工确认标记。

门槛未通过时，页面展示具体字段或原因；按提示补齐后重新校验。

### 6. 接受、退回、拒绝

- **接受并生成修订**：生成不可变修订，进入 release-check 候选集。
- **退回**：要求补充或修改，不生成已接受修订。
- **拒绝**：记录拒绝理由，不进入发布清单。
- **合并**：把重复候选合并到目标能力，仍需满足证据与门槛要求。

已接受修订不可原地修改；再次修改会生成新的修订号。

## 九、发布前检查

进入“发布与回滚”，系统调用 release-check：

- 是否至少存在一个未发布的已接受修订；
- 每个能力的门槛是否通过；
- 是否存在未解决冲突；
- 修订是否已在当前清单；
- 覆盖缺口是否已确认。

只有 `publishable=true` 时才允许发布。若返回：

- `NO_ACCEPTED_REVISION`：还没有可发布的已接受修订。
- `NO_UNPUBLISHED_ACCEPTED_REVISION`：当前已接受修订都已在该发布清单中，发布器不会重复发布同一清单。
- 其他能力级错误：按条目中的能力 ID 与错误信息回到审核页处理。

## 十、发布

1. 确认 release-check 可发布。
2. 勾选“我已核对覆盖缺口与发布范围”。
3. 填写发布说明。
4. 点击“发布当前审核清单”，在浏览器确认框中确认。
5. 发布成功后会生成不可变 `Publication`，记录清单哈希、发布人、时间与能力数量。
6. 系统切换品类生效指针，但**不会改写历史任务固定的发布引用**。

发布后：

- 再次 release-check 会返回 `publishable=false`，这是预期行为。
- 页面不提供“强制发布”或直接改指针的入口。
- 发布器会重新校验修订、门槛、冲突、覆盖确认与证据回读；证据不可读时失败关闭。

## 十一、回滚

1. 在“发布与回滚”选择历史发布作为回滚目标。
2. 当前生效发布不能被选为目标，页面会禁用该行。
3. 二次确认后提交。
4. 服务端校验目标发布、期望生效发布 ID、清单哈希与证据回读。
5. 成功后切换指针并写 `publication.rollback` 审计。

注意：

- 只有一个发布记录时，页面无法选择历史发布；这是 UI 安全约束，不是服务端缺少回滚能力。
- 回滚只影响后续评估读取的生效发布，不修改历史任务已固定的引用。

## 十二、审计日志

“审计日志”按时间倒序显示：

- `source.upload`：源码上传；
- `index.build`：索引任务；
- `documents.staging_snapshot.derived`：派生文档暂存；
- `document.upload` / `documents.staging.replaced` / `documents.staging.reparse_requested`：文档变更；
- `capability.review.*`：审核动作；
- `publication.publish` / `publication.rollback`：发布与回滚。

可按品类、动作与操作者筛选。审计接口只读，页面不提供删除或修改。

## 十三、常见错误与处理

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 401 | 未登录或令牌缺失 | 重新粘贴管理员令牌 |
| 403 | 普通用户令牌或权限不足 | 使用管理员令牌；不要尝试绕过前端 |
| 409 `DOCUMENT_IN_USE` | 文档已被审核证据引用 | 不删除/替换；新建文档或派生新暂存快照 |
| 409 `DOCUMENT_STAGING_REQUIRED` | 在已发布快照上改文档 | 从当前源码派生新的文档暂存快照 |
| 413 `DOCUMENT_TOO_LARGE` | 文件超过服务端上限 | 压缩或拆分文档，确认仍可读 |
| 422 `INVALID_MEDIA_TYPE` / `INVALID_SIGNATURE` | MIME 或文件签名不符 | 使用真实 DOCX/PDF/XLSX，不要改扩展名伪装 |
| 422 `INVALID_DOCUMENT_TYPE` | 扩展名不在管理员白名单或路径非法 | 使用 DOCX/PDF/XLSX，文件名不要带路径 |
| 422 `EMPTY_DOCUMENT` | 空文件 | 重新导出或上传有效文件 |
| 索引 `INDEX_INTERNAL_ERROR` | 存储根目录不一致或 worker 未运行 | 检查 `SOURCE_ROOT`/`INGESTION_ROOT` 与 worker 日志 |
| 任务长期 queued/pending | worker 未启动 | 启动 ingestion/index/builder worker |
| 文档长期未 parsed | 解析任务未执行或失败 | 查看任务错误码，启动 worker 后重试 |
| release-check 不可发布 | 无已接受修订、门槛未过或冲突未解 | 回到“能力审核”逐项处理 |
| 发布 409 | 期望生效发布 ID 变化或清单已变化 | 刷新工作区，重新检查后发布，不要重放旧请求 |
| 回滚按钮不可用 | 只有当前生效发布或没有历史发布 | 有历史发布时选择历史项；单发布时不要强行回滚 |

## 十四、安全与操作边界

1. 不使用真实客户资料、未授权产品文档或生产密钥做测试。
2. 不把管理员令牌写入截图、日志、工单或聊天记录。
3. 不手工修改数据库中的快照状态、发布指针或证据哈希。
4. 不通过招标参数上传 API 冒充管理员技术文档上传。
5. 不把合成候选当成真实 WAF 产品能力结论。
6. 发布前必须完成人工逐字段审核；release-check 只是检查，不替代人工判断。
7. 发现证据与描述冲突时，选择冲突/不足并退回，不要为了发布强行勾选“证据支持”。

## 十五、当前限制

1. **仅文档建库不支持**：必须先有已索引受控源码；系统不会伪造源码快照。
2. **管理员前端只放行 DOCX/PDF/XLSX**：后端 `DOCUMENT_SUFFIXES` 仍含 `.md/.txt` 供内部/测试路径使用；管理员入口仍执行扩展名、MIME 与签名校验。
3. **worker 需单独运行**：API 容器不负责启动 ingestion/index/builder worker。
4. **SSO 未接入**：当前为静态令牌，`sso_ready=false`。
5. **验收环境目录需配置**：容器内 `SOURCE_ROOT` 与 `INGESTION_ROOT` 必须一致或正确软链；容器重建后需重新配置。
6. **仅合成资料验收**：P3.1-A 的浏览器验收只使用合成源码与合成 DOCX，不代表真实产品能力通过。
7. **不进入 P3.2/P3.3**：本指南不覆盖真实招标参数评估、生产上线或正式业务结论。

## 十六、一次完整维护的最短路径

1. 管理员登录 → 进入品类工作区。
2. 上传源码 ZIP → 等待解压 → 构建索引。
3. 派生文档暂存快照。
4. 上传 DOCX/PDF/XLSX → 等待解析 → 必要时“刷新文档”。
5. 重建暂存索引 → 发起文档发现。
6. 逐候选登记证据、填写断言、校验门槛、接受修订。
7. release-check 通过 → 勾选覆盖确认 → 发布。
8. 需要时选择历史发布回滚。
9. 在审计日志核对资料、文档、审核、发布与回滚记录。
