# P1.3 运行与复验

## 安装和兼容

基线P1.2整改6f19e3d；保留既有.env、数据库和卷，勿重写0001～0004或清空存储。
`uv sync --frozen`；`docker compose up --build -d --wait --wait-timeout 180`。
api自动升级到0005，`docker compose exec -T api alembic check`应无差异。
现有POST /snapshots/{id}/build仍然只做索引，**没有悄悄改为触发收费模型调用**。
新增独立builder服务，默认单任务，与indexer/retrieval分离。

## 模型准入

仅在本地.env配置BUILDER_MODEL、BUILDER_BASE_URL、BUILDER_API_KEY。
模型端点必须企业批准；OpenAI兼容HTTP(S)接口，不把密钥写在URL里。
BUILDER_ALLOW_SYNTHETIC允许人工公开验收资产；
BUILDER_ALLOW_ENTERPRISE为企业源码单独授权，默认false；不能因允许人工资产就自动外发企业源码。
这些是管理员可信配置，不是自动内容分类或企业审批平台。禁止给普通用户设置分类/发起调查权限。
本批用户批准的测试仅限人工公开源码/文档，企业外发开关保持false。
修改.env后重建builder配置：
`docker compose up -d --no-deps --wait builder`。
不要把完整docker compose config/inspect环境值贴到日志或报告。

可配置每模块请求数8、工具调用30、总Token30000、累计工具上下文80000字符、
单次输出4000Token、模块180秒、任务1800秒，builder默认单并发。
SDK重试设为0，服务层模型/结构重试受预算约束；参数预算覆盖跨显式retry累计计数。
未使用官方用量预估接口（避免不支持端点），因此Token限额是响应后核查，
最多可能超出一个响应；上下文/输出/请求上限同时兜底，不是精确账单硬封顶。
费用单价未知为null，未测用量/请求失败usage_incomplete=true，不将未知记成零费用。
BUILDER_REASONING_EFFORT空值表示供应商默认，支持显式low/high；只在模型确实支持时设置。
本批GLM-5.3-Flash用low，仍强制开启思考，不尝试关闭、不记录推理正文。
官方模型说明及迁移说明表明默认max、可选low/high，4000输出预算包含思考可能先被耗尽：
https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash.md
https://docs.bigmodel.cn/cn/guide/start/migrate-to-glm-new.md
这些是原厂协议说明，不代表第三方网关实际费率；费用仍未知。
无模块名文档命中时只回退读取同快照前5条候选，明确相关性与覆盖率未验证，不当成已关联文档。

## 异步调查

1. 管理员上传源码→extracted，POST /snapshots/{id}/build→indexed，按需上传文档。
2. POST /api/v1/snapshots/{id}/investigate，JSON：
   `{"module_ids":["服务端返回模块ID"],"data_classification":"synthetic_public"}`。
   省略module_ids时选当前快照全部模块，超过24个需分批选择；返回202 job_id，不等待模型。
3. GET /api/v1/jobs/{job_id} 查看请求/工具/Token/耗时/费用估计/模块计数；
   GET /jobs/{id}/investigations 看模块输出与错误。
4. GET /jobs/{id}/investigation-traces?cursor=0&limit=100 查看脱敏工具/模型轨迹，
   按next_cursor翻页；轨迹不保存完整提示、源码、模型推理文本、API密钥。
5. GET /snapshots/{sid}/candidates?category_id={cid} 查看候选和局部关系假设；
   GET /evidence/{eid}?category_id={cid}&snapshot_id={sid} 服务端再次回读核验证据。
   均仅admin后台；普通read仍只查已有生效指针，不暴露暂存知识。
6. 失败/partial可POST /jobs/{id}/retry；已成功模块不重新调用模型或重复插入能力；
   失败模块重跑但保留累计预算、证据和轨迹。预算耗尽不会靠retry自动清零；
   管理员须评估范围/预算，必要时显式创建新任务（新任务可产生新的调查草稿，本批不跨任务合并）。
7. indexed只表示源码索引，review_ready仅表示调查处理完毕待后续审核，
   两者都不是语义已验证、产品已支持或已发布。

## 证据和模型边界

工具仅query_knowledge、register_evidence、get_capability_candidates；
query_knowledge封装原P1.2强类型只读工具，不暴露Shell/网络任意URL/写文件。
登记前必须在本模块运行中完整回读同一定位与哈希，服务端重新回读验证，模型不能伪造ID。
源码证据保存原文件SHA256、精确行区间及引用文本哈希；文档证据还验证原始文档和分段定位。
来源核验source_verified不等于语义验证；能力只candidate/evidence_found，关系只hypothesis，
不存在verified/approved写入口。
仅文档证据标document_claim_unverified；只有测试代码保持candidate；
未接入函数或unresolved调用永远不能因此证明产品可达性。
truncated/coverage_incomplete/unresolved转为模块未验证事项；无结果不能作“不支持”结论。
资料中的AGENTS/README/提示注入都是待分析数据，不能扩展模型工具权限。
