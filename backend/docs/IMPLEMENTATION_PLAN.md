## 系统边界

管理员提前导入源码和技术资料。售前只选品类，不上传源码，不选择产品版本。
内部不可变快照用于溯源，不是面向用户的版本选择功能。

Agent A 是知识工程：静态调查、真实证据、能力画像、隐藏功能与潜在等效候选。
Agent B 是后续参数评估：消费知识库，也可复用同一受限只读工具继续调查完整源码。
能力画像不是封闭功能清单。Agent A 不直接写生产事实，不把候选等效认定为已满足。
本批没有 LLM、Embedding、源码执行或外部源码传输。

## P1.1 实施步骤

1. 锁定 Python 3.12+ 与依赖；分开 api/core/ingestion/jobs/db 及后续模块。
2. 建立品类、快照、任务、导入审计迁移；本批不提前创建能力和证据业务。
3. 最小管理员/只读 Token 鉴权，随机凭据生成，无固定口令。
4. 分块接收、哈希归档、数据库持久化任务，上传响应 202 不等待分析。
5. Worker 通过 outbox 投递 RQ，在隔离目录完成限额校验和静态解压。
6. 返回任务状态、稳定错误码和统计，提供显式重试和重复投递保护。
7. 提供四服务 Compose、健康检查、非 root 与只读源码视图。
8. 运行单元、API 集成、安全与真实 Compose 检查，记录结果并停止新增功能。

## 真实功能与未实现功能

本批导入到 extracted。manifest 中的文件哈希是导入完整性元数据，
不是 evidence_id，不是 source_files 数据库索引，也不是能力记录。
P1.3 前不能提供“输入→工具→证据 ID→能力”的真实链路，因此不得生成假证据样例。
后续工具应遵循规格第 7 节 RunContext 绑定作用域和统一 Pydantic envelope；
本批不暴露空实现工具，不接入 Agent B。
