## 二、独立验收环境

新建独立 Compose 项目 `product-knowledge-p31b`，与既有环境在项目名、端口、数据库、Redis 库和存储卷上完全隔离。

| 项目 | 配置 |
| --- | --- |
| 编排文件 | `backend/docker-compose.p31b.yml` |
| Compose 项目 | `product-knowledge-p31b` |
| 管理员页面 | `http://127.0.0.1:18180/#/admin` |
| API | `http://127.0.0.1:18190` |
| Retrieval | `http://127.0.0.1:18191` |
| 数据库 | PostgreSQL `knowledge_p31b`，迁移 `0012` |
| Redis | db `6`，独立队列 |
| 镜像 | `product-knowledge:p31b-6b8772b`、`product-knowledge-p31b-frontend:6b8772b` |
| 服务 | api、worker、indexer、builder、taskworker、retrieval、frontend、postgres、redis |
| 存储 | 独立命名卷：archives、ingestion、documents、control、tender、exports、postgres_data、redis_data |

统一入口：

```bash
cd backend
scripts/p31b_env.sh init      # 生成 .env.p31b，随机令牌，权限 600，不覆盖
scripts/p31b_env.sh build     # 从当前 HEAD 构建后端与前端镜像
scripts/p31b_env.sh start     # 启动并等待健康检查
scripts/p31b_env.sh status    # 服务、健康、迁移、路径、worker 心跳
scripts/p31b_env.sh restart   # 重启并等待健康检查
scripts/p31b_env.sh logs      # 跟随日志
CONFIRM=1 scripts/p31b_env.sh reset  # 仅删除本项目容器、网络与数据卷
```

环境关键设计：

- `SOURCE_ROOT` 与 `INGESTION_ROOT` 都指向 `/data/ingestion`，不再依赖 P3.1-A 的人工软链。
- `BUILDER_ALLOW_SYNTHETIC` 与 `BUILDER_ALLOW_ENTERPRISE` 在 Compose 中强制为 `false`，不继承 `.env`。
- `TENDER_QUEUE_ENABLED`、`EVALUATION_QUEUE_ENABLED`、`EXPORT_QUEUE_ENABLED` 为 `true`，由独立 `taskworker` 消费。
- 前端使用 nginx 容器提供真实管理员页面，`VITE_API_BASE=/` 反向代理 `/api/`。
- Dockerfile 创建 `/data/tender`、`/data/exports` 并设置应用用户属主，避免命名卷 root 属主导致写入失败。

干净启动结果（`docs/acceptance/p31b_final_env_6b8772b.log`）：
