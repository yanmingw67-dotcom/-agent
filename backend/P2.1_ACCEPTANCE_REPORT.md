### 3.1 独立数据模型与迁移

### 3.2 结构恢复

- `backend/app/tender/structure.py`
  - DOCX：段落、标题、表格、合并单元格、页眉页脚去除、表头行/数据行区分。
  - XLSX：多 Sheet、表头识别、合并分类继承、公式不计算、外部链接不加载。
  - PDF：逐页文本、跨页表格、重复页眉页脚去除；空页/扫描页生成 `parse_gap`，扫描页标记 `ocr_required`，不调用 OCR、不伪造内容。
  - 统一区域对象保留 `section/locator/table/row/column/page/sheet` 等定位信息。
- Office 预检复用现有 `validate_office`，并增加 P2.1 专用拒绝规则：宏（`vbaProject.bin`）、ActiveX、嵌入对象、外部关系文件、XLSX 外部工作簿链接；PDF 拒绝 JavaScript 和嵌入文件。
- 文件大小、页数、Sheet 数、行数、列数、文本量和参数数量都有上限。

### 3.3 规则与覆盖

- `backend/app/tender/rules.py`
  - 顶层参数由结构决定：编号条款、表格数据行、无编号独立段落；内部 `(1)(2)(3)` 或枚举只生成子要求。
  - 过滤编制说明、填写指南、证明材料/截图/检测报告/证书/承诺函、商务售后、友商对比、页眉页脚、页码、重复表头、备注。
  - “支持日志导出 PDF”保留；“提供 PDF 检测报告”过滤。
  - 每个区域写入 `extracted/filtered/ambiguous/parse_gap` 之一；没有无痕丢弃。
  - `______` 阈值不补造数值：`threshold=null` 且 `ambiguity="blank_threshold"`。
  - 超过参数预算时记 `ambiguous + PARAMETER_LIMIT`，不静默截断。
  - 无法判断的段落记 `UNCERTAIN_PARAMETER`，保留原文等待人工确认。

### 3.4 服务与 API

- `backend/app/tender/service.py`
  - 文本/文件任务创建、幂等键、活跃任务上限、后台执行、失败/部分成功状态。
  - 独立存储根 `settings.tender_store`，文件权限 `0750/0640/0440`，服务端生成随机存储键。
  - 参数编辑、确认、拆分、合并、新增；所有动作写 `tender_corrections`，保存 before/after 和 correlation_id。
  - 参数排序调整使用整体偏移，避免 SQLite 唯一约束在拆分/合并时的瞬时冲突。
  - 任务读取严格按 `principal_id` 过滤；管理员不会自动读取其他 principal 的招标任务。
- `backend/app/tender/api.py`
  - `POST /api/v1/tender/extractions`
  - `POST /api/v1/tender/extractions/upload`
  - `GET /api/v1/tender/extractions`
  - `GET /api/v1/tender/extractions/{job_id}`
  - `GET /api/v1/tender/extractions/{job_id}/result`
  - `GET /api/v1/tender/extractions/{job_id}/coverage`
  - `POST /api/v1/tender/extractions/{job_id}/retry`
  - 参数编辑/确认/拆分/合并/新增接口。
- `backend/app/tender/schemas.py`：请求字段长度限制；不接受客户端提供的参数/任务 ID。

## 6. 安全与隔离说明

- 招标正文保存在独立 `tender_*` 表及独立存储根；没有写入 `capability_claims`、`snapshots` 或发布表。
- 请求日志只记录方法、状态、耗时、correlation_id 等元数据；`run_tender_job` 不打印正文、文件名全文或模型提示。
- 上传路径使用服务端随机键，拒绝路径分隔符/控制字符；文件权限受限。
- 宏、ActiveX、嵌入对象和 Office 外部关系在被解析前拒绝；XLSX 不计算公式；PDF 不执行 JavaScript。
- 任务读取严格按 `principal_id` 过滤；管理员不会因为持有 admin token 自动读取或上传他人的招标文件。
- 当前只有 admin/read 两种共享 token，`principal_id` 实质上是 token 角色，不是完整的用户账号体系；真实多用户隔离仍需在接入账号系统后复测。

## 7. 明确限制和未覆盖项

1. **真实文件不可用**：工作区没有《WAF招标技术参数表.docx》；15/45 的数字来自合成 fixture，不能替代真实附件验收。
2. **未接入模型**：没有调用外部模型做边界识别、歧义补充或子要求拆解；规则无法判断的段落会进入 `ambiguous`，不会自动补造。
3. **PDF 未做 OCR**：扫描页只记录 `ocr_required` 和覆盖缺口；没有真实 OCR 准确率数据。
4. **没有真实多用户账号**：只有 admin/read token；用户隔离测试是 principal 级别的模拟。
5. **没有前端**：本轮只交付后端 API、数据层、测试和报告。
6. **性能不是 SLA**：采样数据来自本地开发机，未在目标部署环境做并发、内存和长文件压力测试。
7. **真实 PDF/Excel 变体覆盖有限**：真实文件可能包含复杂嵌套表、图片表格、特殊合并方式或公式缓存缺失，需要真实附件回归。
