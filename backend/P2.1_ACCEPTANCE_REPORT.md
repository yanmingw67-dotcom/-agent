## 6. 安全与隔离说明

- 招标正文保存在独立 `tender_*` 表及独立存储根；没有写入 `capability_claims`、`snapshots` 或发布表。
- 请求日志只记录方法、状态、耗时、correlation_id 等元数据；`run_tender_job` 不打印正文、文件名全文或模型提示。
- 上传路径使用服务端随机键，拒绝路径分隔符/控制字符；文件权限受限。

- 任务读取严格按服务端认证上下文中的 `principal_id` 过滤；管理员不会因为持有 admin token 自动读取或上传他人的招标文件。

## 8. 第一轮审核整改 R01～R04

### R01 身份与用户隔离

- 新增强类型 `Identity` 和 `current_identity()`；`principal()` 保持返回角色字符串以兼容 P1.1～P1.6，P2.1 全部路由改用 `tender_principal()`，用户 ID 只来自认证上下文。
- 共享 read token 固定为 `read-shared`，admin token 固定为 `admin`；`READ_USER_TOKENS` 支持配置多个普通用户 Token，并校验用户 ID、Token 长度、保留名、重复 Token 和与 admin/read Token 互异。
- 新增 `test_p21_identity.py`：alice 与 bob 两个普通用户分别创建任务，互相对任务、结果、覆盖、重试、重新提取、编辑、确认、拆分、合并、新增全部 404；共享 read 和 admin 也不能读取 alice 的任务；数据库 owner 分别为 alice/bob。

### R02 有界模型辅助

- 新增 `app/tender/model.py`，结构解析仍是第一层；只挑选 `ambiguous` 区域和带逻辑歧义/复杂逻辑的候选区域，按批量、上下文、请求和 Token 上限调用模型。
- 模型只能返回服务端提供的 `region_id` 和逐字引文；服务端验证区域归属、引文子串、边界、证明材料/商务/竞品内容。`include` 使用原始区域文本生成候选并标记 `review_required=true`；`missing_item` 只记录缺口；`subclause_hint` 只写已校验提示，不删除或改写不确定条款。
- 复用 P1.6 的 `configured_model()` 授权、Pydantic AI 和审计；审计记录 payload/response 哈希、Token 用量、批次、接受/拒绝/缺口，不记录区域正文。模型不可用、请求/Token 预算超限、上下文超限或运行异常写入 `DEGRADED`，并保持 coverage 不完整，绝不宣称语义分析已完成。
- `test_p21_model.py` 使用 FunctionModel 验证：有效锚点被接受，伪造引文、越界 `region_id`、凭空 `missing_item` 被拒，审计不含正文；模型不可用返回 `DEGRADED`。真实模型质量未执行，单独列为未验收。
