## 一、验收范围

本轮验收的是“管理员能否在浏览器端完成受控知识维护”，包括：

1. 管理员与普通售前的服务端权限隔离。
2. 受控源码 ZIP 上传、索引与工作区聚合。
3. 从已索引源码派生文档暂存快照。
4. 管理员技术文档上传、解析、同名保留、替换、重解析、删除边界。
5. 文档独立发现产生候选。
6. 候选逐字段证据绑定、语义确认、门槛校验与人工接受。
7. 发布前检查、复用既有发布器发布、发布后阻止重复发布。
8. 回滚指针切换与发布/回滚审计。
9. 模型授权不可由前端覆盖。
10. P2.1–P2.3 回归、全量 pytest、PostgreSQL 迁移回退、Ruff、TypeScript 与生产构建。

不在本轮范围：

- 真实 WAF 产品资料验收。
- P3.2 真实招标参数评估。
- P3.3 生产上线/正式业务结论。
- 完整 SSO、组织架构或多管理员审批流。
- “仅有技术文档、没有源码”的建库能力。

## 四、浏览器端到端结果

实际走通的链路与标识：

1. 管理员身份进入 `/#/admin`，概览返回 1 个品类 `waf_p31`，限制字段 `document_only_build_supported=false`。
2. 上传合成源码 ZIP 9,928 字节，生成快照 `929e11e9-7ca4-4625-8c6a-e445135a4ad2`。
3. 首次索引因容器目录不一致失败；修正软链后索引成功 `extracted/indexed`。

5. 上传合成 DOCX 37,516 字节，解析为 `parsed`、39 个分段；服务端记录 SHA-256 `97836f5481ccd7a2…`。
6. 重建暂存快照索引成功；文档发现 run `4c4b9b79-8d83-484a-80aa-98c69e62915d`，模式 `structural`，生成 7 个候选。

## 六、安全与边界复核

1. **权限**：`/admin/*` 全部依赖服务端管理员身份；普通用户令牌返回 403，未登录 401。前端隐藏入口不作为安全边界。
2. **文件上传**：校验扩展名、MIME、文件签名、空文件、大小、路径；同名不覆盖；替换要求类型一致；已发布快照与已引用证据的文档禁止原位修改。
3. **路径**：上传文件名 `../escape.docx` 返回 422 `INVALID_DOCUMENT_TYPE`；存储键由服务端生成，不使用客户端路径。
4. **模型授权**：请求体中的 `allow_model`、`frontend_can_override` 不能绕过服务端授权；管理员页只展示服务端状态。
5. **发布**：release-check 仅作展示，真正发布仍由 Publisher 重新校验修订、门槛、冲突、覆盖确认与证据回读；前端不能直接改指针。
6. **暂存隔离**：文档修改只在 `extracted + document_update` 派生快照中允许；已发布快照拒绝原位覆盖。
7. **审计**：资料更新、文档变更、重解析、发布、回滚写审计；审计接口只读。
8. **敏感信息**：本轮日志未写入管理员/普通用户令牌、数据库密码或 API Key；验收截图不含令牌明文。

## 七、已知限制与残余风险

1. **仅文档建库不支持**：没有已索引受控源码时不能派生文档暂存快照。系统不会伪造源码快照，也不会用招标参数上传 API 冒充管理员文档上传。该限制已通过 `limits.document_only_build_supported=false` 暴露。
2. **后端文档后缀比管理员前端宽**：`DOCUMENT_SUFFIXES` 仍含 `.md/.txt`，供内部/测试路径使用；管理员前端只放行 DOCX/PDF/XLSX。若要将后端管理员入口也收紧为三类，需要单独评估对既有 P1.6 测试与内部导入的影响，本轮未改动。
3. **回滚 UI 需要历史发布**：回滚按钮禁用当前生效发布，因此单发布记录时只能通过服务端回滚接口验证。多发布记录时页面可选择历史发布并二次确认。该限制是 UI 安全约束，不是服务端能力缺失。
4. **验收容器需要手工 worker**：容器未内置进程管理；验收时必须单独启动 ingestion/index/builder worker，否则任务停留在 queued/pending。
5. **验收容器目录配置**：`SOURCE_ROOT` 与 `INGESTION_ROOT` 不一致导致首次索引失败；已用软链临时修正，容器重建后需重新配置。
6. **SSO 未实现**：当前为静态令牌，保留了 `auth_mode`、`sso_ready` 结构，但没有组织登录、会话刷新或角色同步。
7. **仅合成资料**：本轮 7 个候选与 1 条发布均来自合成 DOCX；不得将“部署接入能力”等描述当成真实 WAF 产品能力结论。
8. **未做生产部署**：未修改共享生产环境、正式数据库、正式存储或正式发布物。

## 八、对 P3.1 既有结论的影响

本轮 P3.1-A 只解决“管理员工作台缺失（ADMIN_API_ONLY）”问题，不改变 P3.1 真实业务验收的阻塞项：

- 真实 WAF 招标参数评估仍为 BLOCKED。
- 本轮没有用管理员工作台的合成验收替代真实招标参数验收。
- 正式库仍为 `0007`，本轮未写入。
- 不宣布生产上线，不进入 P3.2/P3.3。

## 九、验收结论

在**合成测试资料**范围内，P3.1-A 管理员产品知识维护工作台满足本轮功能、权限、文件边界、审核发布、审计与回归要求，验收通过。

建议人工复审重点：

1. 管理员接口是否还有未覆盖的越权路径。
2. 文档暂存源码回退逻辑是否符合业务对“基础源码”的定义。
3. 发布/回滚审计字段是否满足审计留痕要求。
4. 是否接受“仅文档建库不支持”的当前限制，或单独立项。
5. 是否在后续阶段收紧后端管理员文档后缀并接入 SSO。
